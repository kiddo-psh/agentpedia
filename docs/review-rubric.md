# 기사 리뷰 기준표

[작성 가이드](writing-guide.md)의 판단 기준을 점수로 매기는 표입니다. 리뷰어(사람 또는 에이전트)는 항목마다 **1~5점과 근거, 고칠 점**을 남깁니다.
**모든 항목 4점 이상**이면 사람 최종 검수로 넘어가고, 하나라도 3점 이하면 수정합니다. 사실 오류는 점수와 관계없이 반려합니다.

## A. 사실 정확성 (팩트체커)

| 점수 | 기준 |
|---|---|
| 5 | 모든 주장이 출처로 확인되고, 날짜와 인용이 원문과 일치한다 |
| 4 | 사소한 표현 차이만 있고 의미는 정확하다 |
| 3 | 출처로 확인되지 않는 주장이 1개 있다 |
| 1~2 | 출처와 다른 주장, 지어낸 인용, 틀린 날짜가 있다 → **반려** |

확인할 것:
- 각 주장마다 어느 출처의 어디에 근거하는지 짚을 수 있는가
- `<Quote>` 문장이 원문과 글자 그대로 같은가, 타임스탬프가 맞는가
- `publishedAt`이 원문에서 확인한 날짜인가
- 2차 출처만 근거인 주장에 그 사실이 드러나 있는가

## B. 이야기와 가독성 (편집자)

| 점수 | 기준 |
|---|---|
| 5 | 장면으로 시작해 긴장과 전환이 있고, 끝까지 한 흐름으로 읽힌다 |
| 4 | 흐름은 좋으나 한두 섹션이 나열식이다 |
| 3 | 요약문처럼 읽힌다. 인물과 맥락이 약하다 |
| 1~2 | 정보 나열. 섹션 사이 연결이 없다 |

확인할 것:
- 첫 문단이 장면이나 인물로 시작하는가
- 섹션 제목만 읽어도 흐름이 이어지는가
- 한계나 반론을 다루는가
- 과장 표현, 번역투, 긴 문장이 있는가
- `brief` 세 줄만 읽어도 무슨 일인지, 왜 중요한지, 무엇을 할 수 있는지 아는가 (없으면 최대 3점)
- 같은 개념을 한 용어로 쓰는가, 낯선 용어가 처음 나올 때 `<Term>`으로 표시했는가

## C. 시점 명확성 (편집자)

| 점수 | 기준 |
|---|---|
| 5 | 독자가 어느 문단에서든 "언제 기준 이야기인지" 안다 |
| 3 | 출처 목록에만 날짜가 있고 본문에는 없다 |
| 1 | 시점이 틀렸거나 오래된 정보를 현재처럼 쓴다 |

## D. 키트 명확성과 안전성 (키트 리뷰어)

| 점수 | 기준 |
|---|---|
| 5 | `goal`·`changes`·`doesNotDo`만 읽고도 무슨 일이 일어날지 정확히 안다. 프롬프트가 이와 일치한다 |
| 4 | 대체로 명확하나 바뀌는 파일 하나가 모호하다 |
| 3 | 프롬프트가 `changes`에 없는 일을 시킨다 |
| 1~2 | 승인 없이 변경하거나, 권한 우회·대량 삭제 등 위험한 지시가 있다 → **반려** |

확인할 것:
- 프롬프트에 "맞지 않으면 멈춤", "계획 후 승인", "실행해서 확인" 지시가 있는가
- 체크리스트가 `goal`을 실제로 검증하는가
- `tryIt`이 읽기 전용인가 (파일 수정이나 상태 변경을 시키면 3점 이하), 그리고 키트를 돌릴지 판단할 결과를 내는가
- 이 기사의 아이디어를 실제로 구현하는 키트인가 (기사와 무관한 일반론이 아닌가)

## E. 인물과 이미지 (팩트체커)

| 점수 | 기준 |
|---|---|
| 5 | 인물 소개가 정확하고, 사진이 있다면 라이선스와 출처가 확인된다 |
| 3 | 인물 소개가 모호하다 |
| 1 | 라이선스를 확인할 수 없는 사진을 썼다 → **반려** |

## 리뷰 결과 형식

```json
{
  "scores": { "facts": 5, "story": 4, "timing": 5, "kit": 4, "people": 5 },
  "blocking": ["반려 사유. 없으면 빈 배열"],
  "fixes": [{ "where": "## 1. 병렬 세션 둘째 문단", "problem": "…", "suggestion": "…" }]
}
```
