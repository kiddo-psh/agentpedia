# 점검 체크리스트

## 목록
- [ ] 에이전트 워크플로 단계를 실제 파일에서 확인해 모두 적었다.
- [ ] 해당하지 않는 레포라면 아무것도 바꾸지 않고 이유만 알렸다. 승인하지 않았다면 파일을 만들지 않고 요약만 보여 줬다.
- [ ] 각 단계에 근거 파일 경로를 붙였다.
- [ ] 각 단계가 모델이 혼자 못 한다고 가정하는 것을 한 문장으로 적었다.

## 진단
- [ ] 각 단계에서 만든 쪽과 검증하는 쪽이 같은지 표에 적었다.
- [ ] 완료 기준을 작업 전에 정했는지, 검증이 실행까지 하는지 단계마다 표시했다.
- [ ] 완료 기준이 실행으로 확인되지 않는 항목을 표시했다.
- [ ] 줄여 볼 후보를 "하나씩 빼서 비교해 볼 대상"으로만 적었고, 글의 비용·시간 수치를 이 레포 예측으로 쓰지 않았다.
- [ ] 실제 워크플로 하나에 대한 maker≠evaluator 분리 제안 초안을 적었고, 구현하지 않았다.
- [ ] 평가 쪽도 LLM이면 관대할 수 있다는 한계를 적었다.

## 변경
- [ ] 가정 보고서와 분리 제안 파일을 각각 승인받았고, 승인받지 않은 항목은 건너뛰었다.
- [ ] `docs/`가 없었다면 폴더를 만드는 것도 승인받았다.
- [ ] 같은 이름 파일이 있으면 덮어쓰지 않고 승인받은 다른 이름을 썼다.
- [ ] 테스트·린트를 실행했다면 승인 후 실행했고, 직후 `git status --short --ignored`에 새 파일이 없음을 확인했다(있으면 지우지 않고 경로를 적었다).
- [ ] 실행한 명령(없으면 "실행 안 함")과 직후 `git status`를 가정 보고서에 적었다.
- [ ] 분리 제안 파일에 역할·입력·실행 채점 기준·관대함 한계·한 구성요소씩 재평가 주의가 있다(만들었다면).
- [ ] 보고서에 로컬·홈 설정 내용을 옮기지 않고 경로와 단계 이름만 적었다.
- [ ] 에이전트 설정, 훅, 스크립트, 지침 파일, 애플리케이션 코드는 수정하지 않았다.
- [ ] `git status --short`(또는 파일 목록 비교)에서 바뀐 파일이 승인한 문서뿐이다.
- [ ] 만든 파일에 비밀 값 패턴이 없음을 grep과 눈으로 확인했다.
