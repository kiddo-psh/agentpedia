# 점검 체크리스트

## 목록
- [ ] 에이전트 워크플로의 단계를 실제 파일(0단계에 나열한 지침 파일, `.claude/` 아래 설정, `.cursor/rules/*.mdc`, 레포 안의 훅·스크립트·프롬프트 파일, 읽기 전용 홈 설정)에서 확인해 모두 적었다.
- [ ] 해당하지 않는 레포라면 아무것도 바꾸지 않고 이유만 알렸다. 사용자가 승인하지 않았다면 파일을 만들지 않고 요약 표만 보여 주고 끝냈다.
- [ ] 각 단계에 근거 파일 경로를 붙였다.
- [ ] 각 단계가 모델이 혼자 못 한다고 가정하는 것을 한 문장으로 적었다.

## 진단
- [ ] 각 단계에서 결과물을 만든 쪽과 검증하는 쪽이 같은지 표에 적었다.
- [ ] 완료 기준을 작업 전에 정했는지, 검증이 실행까지 하는지 단계마다 표시했다.
- [ ] 완료 기준이 실행으로 확인되지 않는 항목을 표시했다.
- [ ] 줄여 볼 후보를 "하나씩 빼서 비교해 볼 대상"으로만 적었고, 글의 비용·시간 수치를 이 레포의 예측으로 쓰지 않았다.

## 변경
- [ ] 보고서를 만들기 전에 1~2단계 요약과 만들 파일을 보여 주고 사용자의 승인을 받았다.
- [ ] `docs/`가 없었다면 폴더를 만드는 것도 승인받았다.
- [ ] `docs/harness-assumptions.md`가 이미 있었다면 덮어쓰지 않고 승인받은 다른 이름을 썼다.
- [ ] 테스트·린트를 실행했다면 승인을 받은 뒤 실행했고, 직후 `git status --short --ignored`에 새 파일이 없음을 확인했다(git이 아니면 실행 전후 파일 목록을 비교했다. 나왔다면 지우지 않고 경로를 보고서에 적었다).
- [ ] 실행한 명령(없으면 "실행 안 함")과 직후 `git status` 결과를 보고서에 적었다.
- [ ] 보고서에 CLAUDE.local.md, .claude/settings.local.json, ~/.claude, ~/.codex의 내용을 옮기지 않고 경로와 단계 이름만 적었다.
- [ ] 단계 표에 단계 이름, 근거 파일, 가정, 같은 쪽 여부, 완료 기준 확인 방식이 모두 있다.
- [ ] 에이전트 설정, 훅, 스크립트, 애플리케이션 코드는 수정하지 않았다.
- [ ] `git status --short`(git이 아니면 파일 목록 비교)에서 바뀐 파일이 보고서와 승인한 지침 파일뿐이다.
- [ ] 지침 파일에 한 줄을 넣었다면, 승인 요청에 대상 파일과 고른 이유, 그 파일을 Claude Code와 Codex 중 어느 쪽이 읽는지 적었고 승인받은 파일에만 넣었다. 지침 파일이 없었다면 새로 만들지 않고 건너뛰었다.
- [ ] 사용자가 승인한 파일만 바꿨고, 지침 파일을 고쳤다면 `git diff`에 승인한 한 줄만 있다.
- [ ] 보고서 파일에 비밀 값 패턴이 없음을 grep과 눈으로 확인했다.
