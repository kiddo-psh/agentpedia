# 점검 체크리스트

## 목록
- [ ] API(OpenAPI, 라우트, 문서)의 위치와 인증 방식 이름을 적었다.
- [ ] CLI가 있는지 확인했다. `--help`는 소스를 읽어 상태를 바꾸지 않음을 확인하고 승인받은 명령만 실행했고, 그렇지 않은 것은 '실행 안 함'으로 적었다(설치, 로그인 같은 명령은 실행하지 않았다).
- [ ] `SKILL.md`와 스킬 디렉터리가 있는지 확인했다.
- [ ] 이 레포가 제공하는 MCP 서버와 연결해 쓰는 MCP 서버를 구분해 적었다.
- [ ] `AGENTS.md`, `CLAUDE.md`, README의 에이전트용 안내를 확인했다.

## 판단
- [ ] 각 접점에 있음, 부분, 없음을 붙였다.
- [ ] 브라우저 없이 대표 작업을 끝낼 수 있는지 한 문장으로 적었다.
- [ ] 확인하지 못한 항목은 추측하지 않고 "확인 못 함"이라고 적었다.

## 변경
- [ ] `docs/agent-surface-audit.md`에 점검 날짜, 접점별 표(위치, 상태, 빠진 것), 빠진 부분, 권장 순서가 모두 있다. 권장 순서의 각 항목에는 그 접점을 열면 에이전트가 끝낼 수 있게 되는 대표 작업이 한 가지씩 적혀 있다.
- [ ] (README를 승인한 경우) 추가한 안내에 설치, 인증, 대표 명령이 있고 인증은 방식의 이름만 적었다.
- [ ] README에 넣은 명령은 레포의 기존 문서에 있는 것이고, 실행 확인한 것('확인함')과 '실행 안 함'이 구분돼 있다.
- [ ] 0단계에서 맞지 않으면 파일을 바꾸지 않고 멈췄거나, 맞다고 판단한 근거를 적었다.
- [ ] 3단계 계획을 보여주고 사용자 승인을 받은 뒤에 `docs/agent-surface-audit.md`를 만들었다.
- [ ] 애플리케이션 코드와 API 동작은 수정하지 않았다.
- [ ] CLI, 스킬, MCP 서버를 만들거나 배포하지 않았다.
- [ ] README 변경은 사용자가 승인했고 루트 `README.md`가 이미 있을 때만 했다. 없으면 새로 만들지 않고 초안을 보고서 끝에 실었다.
- [ ] 레포 안의 스크립트나 바이너리를 실행하는 명령은 정확한 명령줄을 보여 승인받은 것만 실행했다.
- [ ] 같은 이름의 파일이 이미 있으면 덮어쓰지 않고 파일명을 물었고, `docs/`를 만들었다면 승인받았다.
- [ ] 외부 서비스에 접속하거나 계정을 만들지 않았고, 설치, 로그인, API 호출 명령은 실행하지 않았다.
- [ ] `git status --short`(git 레포가 아니면 파일 목록 비교)로 확인해, 변경된 파일이 승인받은 `docs/agent-surface-audit.md`(와 승인한 경우 `README.md`)뿐이다.
- [ ] `docs/agent-surface-audit.md`와 README 변경분에 값 형태의 비밀 패턴(`Bearer [A-Za-z0-9._-]{20,}`, `sk-[A-Za-z0-9]{20,}`, `ghp_[A-Za-z0-9]{20,}`, `AKIA[0-9A-Z]{16}`, `xox[abp]-`, `-----BEGIN`)이 없음을 줄 내용을 출력하지 않는 grep으로 확인했다. 'Bearer 방식' 같은 방식 이름은 허용한다.
