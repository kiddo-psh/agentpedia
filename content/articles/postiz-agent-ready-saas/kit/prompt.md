# 목표: 내 서비스를 코딩 에이전트가 쓸 수 있는 접점(API, CLI, 스킬, MCP, 에이전트용 문서)이 얼마나 갖춰졌는지 점검하기

Postiz 창업자 Nevo David는 2026년 3월 인터뷰에서 오픈소스 SNS 예약 도구 Postiz의 API를 CLI, 스킬, MCP로 열어 에이전트가 직접 쓰게 했다고 말했다. 이 키트는 내 프로젝트가 같은 접점을 얼마나 갖췄는지 찾아 보고서로 남긴다. 기본은 **읽기 전용 점검**이다.

## 절대 지킬 것

- API 키, 토큰, 비밀번호의 **값을 읽어서 출력하거나 보고서에 적지 않는다.** 이름과 위치만 다룬다.
- 애플리케이션 코드와 API 동작을 수정하지 않는다.
- CLI, 스킬, MCP 서버를 새로 만들거나 npm 같은 외부 레지스트리에 배포하지 않는다.
- 외부 서비스에 접속하거나 계정을 만들지 않는다.
- 파일, 패키지, 시스템 상태를 바꾸는 명령은 실행하지 않는다.

## 0. 맞는지 먼저 판단하기

아래를 확인한다. 해당하지 않으면 **아무것도 바꾸지 말고 멈춘 뒤** 이유를 알린다.

- 이 레포가 다른 사람이나 에이전트가 쓸 서비스, 라이브러리, API를 제공한다. (앱 내부 코드뿐이고 외부에 여는 것이 없으면 맞지 않는다.)
- 현재 디렉터리가 사용자가 작업하는 레포다.

## 1. 접점 목록 만들기 (읽기 전용)

있는 것만 확인한다. 없으면 "없음"으로 적는다. 명령은 추측하지 말고, 실행 전에 실행할 명령 목록을 먼저 보여주고 레포 안의 스크립트나 바이너리를 직접 실행하는 명령(예: `node ./bin/x.js --help`)은 확인을 받은 뒤 실행한다. 상태를 바꾸지 않는 `--help`, `--version` 같은 명령만 실제로 실행해 결과를 확인한다. 설치, 로그인, API 호출처럼 외부에 접속하거나 상태를 바꾸는 명령은 실행하지 않고 '실행 안 함'이라고 적는다.

- **API**: OpenAPI 파일, 라우트 정의, API 문서 위치. 인증 방식(방식의 이름만)
- **CLI**: `package.json`의 `bin`, `pyproject.toml`의 scripts, `cmd/` 디렉터리 등. `--help` 출력이 있으면 실행해 대표 명령을 적는다.
- **스킬**: `SKILL.md` 파일, `.claude/skills/`, `skills/` 디렉터리
- **MCP 서버**: 이 레포가 제공하는 MCP 서버 코드나 설정. 레포가 연결해 쓰는 MCP 서버와 구분한다.
- **에이전트용 문서**: `AGENTS.md`, `CLAUDE.md`, README의 설치·인증·대표 사용 예 항목

## 2. 빠진 부분 판단하기

각 접점을 다음 기준으로 표시한다.

- **있음**: 문서화돼 있고, 파일이나 설정이 실제로 존재함을 열어서 확인했다(CLI는 `--help` 실행 결과까지 확인).
- **부분**: 있지만 인증, 설치, 사용 예 중 빠진 것이 있거나, 실행 확인을 하지 못했다.
- **없음**: 찾지 못했다.

"브라우저 없이 코딩 에이전트가 이 서비스로 대표 작업 하나를 끝낼 수 있는가"를 한 문장으로 판단해 보고서에 적는다. 추측으로 채우지 않고, 확인하지 못한 항목은 "확인 못 함"이라고 쓴다.

## 3. 계획을 보여주고 승인받기

다음을 보여주고 **사용자의 승인을 받은 뒤에만** 4단계를 진행한다.

- 1~2단계 결과 표 (접점, 위치, 상태, 빠진 것)
- 만들 보고서 파일: `docs/agent-surface-audit.md` (이미 있으면 덮어쓰지 않고 파일명을 묻는다. `docs/`가 없으면 만들어도 되는지 함께 승인받는다)
- 수정할 README: 루트 `README.md`만 대상으로 한다. 추가할 에이전트용 사용 안내 초안(설치, 인증, 대표 명령)을 보여준다. 추가하지 않으려면 "없음"
- 권장 개선 순서

승인하지 않으면 아무 파일도 만들지 않고 1~2단계 결과 표만 보고한 뒤 멈춘다. 일부만 승인하면 승인된 항목만 4단계에서 적용한다.

## 4. 승인된 범위만 적용하기

- `docs/agent-surface-audit.md`를 만든다. 점검 날짜, 접점별 표, 빠진 부분, 권장 순서를 담는다. 권장 순서의 각 항목에는 그 접점을 열었을 때 에이전트가 끝낼 수 있게 되는 대표 작업 하나를 적는다(예: "예약 생성 CLI -> 브라우저 없이 글 예약"). 키나 토큰의 값은 적지 않는다.
- 승인했다면 루트 `README.md`에 안내 초안을 추가한다. 1단계에서 실제로 실행해 확인한 명령만 넣는다.

## 5. 실행해서 확인하기

- 적은 명령 중 `--help`, `--version`처럼 읽기 전용인 명령만 다시 실행해 확인한다. 나머지는 '실행 안 함'으로 표시한다.
- 보고서와 README 변경분에 `sk-`, `ghp_`, `AKIA`, `xox`, `Bearer `, `-----BEGIN` 같은 패턴이 있는지 `grep -l` 또는 `grep -c`로 찾는다. 매칭된 줄의 내용은 출력하지 않는다.
- `checklist.md`의 항목을 하나씩 점검하고 결과를 보고한다.
