# 목표: 시스템 지침·도구 정의를 매 턴 필수와 필요 시 로드로 나누고 캐시 접두를 점검하기

2026년 9월 Jediah Katz, Connor O'Keefe, Calvin Yee는 Cursor가 **시스템 프롬프트를 줄이고 저빈도 도구를 동적 로딩**해 장시간 에이전트 토큰 비용을 낮췄다고 썼다. 기사 claim은 '매 턴 필수 vs 필요할 때만' 분류와 **캐시 경계 앞 안정 접두**다.
이 키트는 레포의 지침·MCP·도구 설명을 그 기준으로 분류해 `docs/token-context-budget-audit.md`에 남기고, 승인 시에만 최소로 옮기거나 줄인다. CLAUDE.md를 '코드로 알 수 있음' 기준으로 지우는 키트나 범용 하네스 판정 키트와 겹치지 않는다. 기본은 **읽기 전용**이다.

## 절대 지킬 것

- API 키·토큰 값을 출력하지 않는다. 설정에 보이면 이름만 적고 `***`로 가린다.
- 홈 전역 설정, 모델·요금제·프로바이더 플래그는 바꾸지 않는다.
- 유료 API를 대량 호출하거나 프로덕션 트래픽을 재현하지 않는다. 측정은 설정 읽기·대략 토큰 추정·이미 있는 로그만.
- `git add`/`commit`/`push`/`stash`를 실행하지 않는다.
- 검증 명령을 `CLAUDE.md`에 덧붙이지 않는다(Boris 키트 범위). 컨텍스트 줄 삭제 감사로 범위를 넓히지 않는다.

## 0. 맞는지 먼저 판단하기

아래를 확인한다. 해당하지 않으면 **아무것도 바꾸지 말고 멈춘 뒤** 이유를 알린다.

- 레포에 `CLAUDE.md`/`AGENTS.md`/`.mcp.json`/`.cursor/`/`.claude/` 중 지침·MCP·도구 정의가 하나 이상 있다.
- 현재 디렉터리가 사용자 레포다.
- `docs/token-context-budget-audit.md`가 이미 있으면 덮어쓰지 말고 이름을 묻는다.

시작 전 `git status --porcelain`과 `git rev-parse HEAD`를 기록한다.

## 1. 상시 컨텍스트 목록 만들기 (읽기 전용)

파일을 읽고 매 세션·매 턴에 실릴 만한 항목만 모은다. 추측하지 말고 파일에서 확인한다.

- 대상: 루트·하위 `CLAUDE.md`/`AGENTS.md`, `.mcp.json`, `.cursor/rules` 등, `.claude/`의 공유 지침(로컬 전용은 읽기만·수정 후보 제외)
- 각 항목: 경로, 대략 분량(줄·문자), 내용 요약(비밀 없이), 쓰임 단서(항상/특정 작업)
- MCP 서버·도구는 이름과 설명 길이만. 인증 헤더·키는 출력하지 않는다.

## 2. 매 턴 필수 vs 필요할 때만으로 분류하기

Cursor 글의 축으로 분류한다.

- **매 턴 필수(고정)**: 거의 모든 작업에 필요하고, 매 요청 앞에 있어야 하는 짧은 지침·고빈도 도구
- **필요할 때만(동적)**: 특정 작업·20%대 이하로 쓰일 법한 MCP·장문 절차·희소 도구 설명
- **접두를 흔듦**: 날짜·환경·유저별 스킬처럼 자주 바뀌어 캐시 접두 앞에 두면 안 될 후보

분류 근거를 한 줄씩 적는다. 사용 빈도를 재지 못했으면 "추정·미측정"이라고 밝힌다.

## 3. 계획을 보여주고 승인받기

다음을 보여 주고 **승인 후에만** 4단계를 진행한다.

- 분류 표와 접두를 흔드는 항목
- 보고서 경로: `docs/token-context-budget-audit.md`
- 제안하는 최소 변경(없으면 "없음"): 저빈도 MCP를 문서화해 상시 목록에서 빼기, 장문 지침을 별도 파일로 옮기고 필요할 때 읽히게 하기, 가변 환경 나열을 고정 접두 뒤로 옮기기. **한 번에 합의한 파일만.**
- 수정 대상은 git 추적 파일만. 미추적이면 권고만. `.claude/settings.local.json`과 홈 파일은 수정하지 않는다.
- 토큰·latency·tool-call error를 전후 비교하는 **방법**만 보고서에 적는다. 이 키트가 유료 벤치를 돌리지는 않는다.
- 보고서와 각 파일 변경은 따로 승인·거절할 수 있다.

## 4. 승인된 범위만 적용하기

- `docs/token-context-budget-audit.md`를 만든다. 날짜, 분류 표, 접두 후보, 권장 측정 방법, 되돌리기를 담는다.
- 승인한 추적 파일만 최소 수정한다. 내용을 창작해 늘리지 말고, 옮기거나 줄이기만 한다.

## 5. 실행해서 확인하기

- 수정한 JSON이 있으면 파서로 **실행해** 확인한다.
- `git diff`·`git status --porcelain`을 실행해 승인 목록과 일치하는지 본다.
- 비밀 패턴 grep으로 보고서·수정 파일을 검사한다.
- `checklist.md`를 항목별로 보고한다.
