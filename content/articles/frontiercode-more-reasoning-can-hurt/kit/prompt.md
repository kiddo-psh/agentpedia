# 손대면 안 되는 경로와 추론 가능한 조건

The Cognition Team은 FrontierCode 2.0에서 추론을 높이면 범위 차단 기준에 걸려 점수가 내려갈 수 있다고 적었다. 맞는 코드를 더 써도 0점이 될 수 있다. 이 키트는 손대면 안 되는 경로와 코드에서 추론 가능한 조건을 표로 남기고, low와 high 비교 칸은 비운다. 검증 명령을 CLAUDE.md에 덧붙이는 일은 Boris Cherny 키트 범위라 하지 않는다.

## 절대 지킬 것

- 승인받기 전에는 파일을 만들거나 고치지 않는다.
- 애플리케이션 코드, 테스트, 린트 설정, CLAUDE.md, AGENTS.md, 에이전트 설정을 수정하지 않는다.
- 모델을 호출하지 않고, 추론 수준을 바꾸지 않으며, 비교 칸에 점수나 통과 여부를 적지 않는다.
- 검증 명령을 CLAUDE.md나 AGENTS.md에 덧붙이지 않는다.
- 커밋, 푸시, PR, 의존성 설치, 배포, 포맷, 스냅샷 갱신을 하지 않는다.
- API 키와 토큰 값은 출력하지 않는다.

## 0. 맞는지 먼저 판단하기

레포를 읽기 전에 `git status --short`를 실행해 시작 상태를 기록한다.

- git 저장소인가
- 에이전트가 고칠 소스 파일이 하나라도 있는가. 확장자는 ts, tsx, js, jsx, py, go, kt, java, rs, rb, php 중 하나로 본다

소스 파일이 없거나 git 저장소가 아니면 이유를 설명한 뒤 여기서 멈춘다. 맞는 과제가 없다고 새 기능을 제안하지 않는다.

## 1. 경로와 조건을 읽기만 해서 모으기

있는 것만 적는다. 없으면 "없음".

- 공개 API로 보이는 파일. 패키지 export, `public` 모듈, 버전이 붙은 SDK 표면. 추측이면 "후보"라고 적고 근거 경로를 붙인다
- 생성 파일과 락파일. `package-lock.json`, `pnpm-lock.yaml`, `yarn.lock`, `Cargo.lock`, 생성 디렉터리
- 이름만 다른 형제 구현. 같은 버그가 옆 경로에 있을 수 있는 파일 쌍. 코드를 열어 확인한 것만
- 이미 있는 평가 문서나 테스트가 "이 파일은 바꾸지 마"라고 적은 문장

점수는 적지 않는다. low와 high 칸은 비워 둘 자리만 표시한다.

## 2. 계획을 보여주고 승인받기

다음만 보여주고 승인을 받은 뒤에 파일을 쓴다. 거절하면 아무것도 쓰지 않는다.

1. `docs/effort-scope-trial.md` 전문. 이미 있으면 `docs/effort-scope-trial-YYYY-MM-DD.md`처럼 날짜를 붙인 이름을 제안한다
2. 표에 넣을 경로와 조건, 그리고 빈칸으로 남길 열
3. `docs/`를 새로 만드는 경우 그 사실

## 3. 승인된 파일만 쓰고 실행해서 확인하기

- 승인한 경로에만 표를 쓴다. 과제 한 줄, 손대면 안 되는 경로, 코드에서 추론한 조건, low 칸, high 칸. 비교 칸은 빈칸이다
- `git status --short`를 다시 실행해, 시작 이후 바뀐 파일이 그 표 하나인지 확인한다. 다른 파일이 바뀌었으면 이번 키트가 쓴 파일만 되돌리고 보고한다
