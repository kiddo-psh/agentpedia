# 목표: Claude가 스스로 검증하고, 팀이 실수를 CLAUDE.md에 쌓아 가는 구조 갖추기

보리스 체르니는 2026년 1월 스레드에서 아마 가장 중요한 팁으로 "Claude에게 자기 작업을 검증할 방법을 주는 것"을 꼽았습니다.
이 레포에 그 검증 루프와, 팀이 함께 고쳐 가는 `CLAUDE.md`를 갖춥니다.

## 0. 먼저 판단하고, 맞지 않으면 멈추기

레포를 읽고 다음을 확인합니다.

- 시작 시점의 `git status --short` 결과를 기록합니다. 커밋되지 않은 변경이 있으면 사용자에게 알리고 계속할지 묻습니다.
- 테스트, 타입 체크, 린트, 빌드 중 하나 이상을 명령으로 실행할 수 있는가 (`package.json` scripts, `Makefile`, `pyproject.toml`, CI 설정 등)
- 기존 `CLAUDE.md`, `.claude/settings.json`, `.claude/commands/`가 있는가

실행할 수 있는 검증 명령이 하나도 없으면 **여기서 멈추고** 그 사실만 보고합니다. 검증 명령을 새로 만들거나 테스트 코드를 추가하지 않습니다.

## 1. 검증 명령을 실제로 실행해 확인하기

찾은 후보 명령을 하나씩 **실제로 실행**합니다. 추측한 명령은 쓰지 않습니다.
실행하기 전에 각 스크립트의 실제 내용(`package.json` scripts 본문, Makefile 타깃 등)을 읽습니다. 배포·퍼블리시·마이그레이션·데이터 삭제·외부 전송을 하거나 의존성을 설치하는 명령은 실행하지 않고 목록에 '건너뜀'으로 적습니다. 의존성이 설치되어 있지 않으면 설치하지 않고 그 사실을 보고합니다. 판단이 애매한 명령은 실행 전에 사용자에게 묻습니다.
명령별로 성공/실패와 걸린 시간을 기록합니다. 실패하거나 실행할 수 없는 명령은 이후 단계에 넣지 않습니다.
실행해서 성공한 명령이 하나도 없으면 여기서 멈추고, 명령별 실패 이유만 보고합니다. 실패를 고치려고 코드나 설정을 바꾸지 않습니다.

## 2. 계획을 보여주고 승인받기

파일을 바꾸기 전에 아래 변경 계획을 보여주고 **사용자의 승인을 받습니다.** 승인받지 않은 항목은 적용하지 않습니다.

1. **`CLAUDE.md`**: 1단계에서 동작을 확인한 명령을 "작업을 끝내기 전에 실행할 명령" 섹션으로 추가합니다. 빌드·테스트·린트 명령도 1단계에서 성공한 것만 적습니다.
   "Claude가 했던 실수" 섹션을 만들어, 앞으로 Claude가 틀릴 때마다 한 줄씩 추가하도록 안내합니다.
   이미 `CLAUDE.md`가 있으면 빠진 부분만 보강하고 기존 내용은 지우지 않습니다. 짧게 유지합니다.
2. **`.claude/settings.json` 권한**: 1단계에서 확인한 안전한 검증 명령만 `permissions.allow`에 추가합니다. 파일을 지우거나 외부로 보내거나 배포하는 명령은 넣지 않습니다. 와일드카드로 범위를 넓히지 않습니다.
   `.claude/settings.json`이 이미 있으면 기존 키와 항목은 그대로 두고 `permissions.allow` 배열과 `hooks`에만 항목을 추가합니다. 계획에는 바뀌기 전과 후의 JSON 차이를 보여줍니다.
3. **`.claude/settings.json` 훅 (포매터가 있을 때만)**: 레포에 파일 경로를 인자로 받는 포매터가 있으면, `Edit|Write` matcher를 쓰고 훅 입력의 `tool_input.file_path`에 있는 파일 하나만 포맷하는 PostToolUse 훅을 추가합니다. 레포 전체를 포맷하는 명령만 있으면 훅을 추가하지 않고 그 이유를 보고합니다. 계획에는 훅에 들어갈 명령 전문을 그대로 보여줍니다. 포매터가 없으면 이 항목은 건너뜁니다.
4. **`.claude/commands/`**: 슬래시 명령 1~2개를 만듭니다. 하나는 1단계에서 성공한 검증 명령을 순서대로 실행하고 결과를 요약하는 명령입니다(예: `verify.md`). 다른 하나는 선택 사항이며, 레포를 읽기만 하거나 1단계 명령만 쓰는 작업으로 한정합니다. 커밋·푸시·PR 생성·배포·파일 삭제를 하는 명령은 만들지 않습니다. 기사의 `/commit-push-pr`은 참고만 하고 이 키트에서는 만들지 않습니다.

## 3. 적용 후 다시 실행해 확인하기

- 추가한 슬래시 명령에 적힌 셸 명령을 그대로 실행해 동작을 확인합니다.
- 훅을 추가했다면, 레포 밖이나 `.claude/` 아래에 임시 파일 하나(예: `.claude/hook-check.<확장자>`)를 새로 만들어 포매터가 실행되는지 확인하고, 확인이 끝나면 그 파일을 지웁니다. 확인 전후로 `git status --short` 결과가 같은지 비교합니다. 다르면 훅을 되돌리고 사용자에게 보고합니다.
- `.claude/settings.json`이 올바른 JSON인지 확인합니다.
- `git status --short`를 시작 시점과 비교해, 새로 생기거나 바뀐 파일이 `CLAUDE.md`, `.claude/settings.json`, `.claude/commands/` 아래뿐인지 확인합니다.

## 하지 않는 일

- `--dangerously-skip-permissions`를 쓰거나, 권한 확인을 통째로 끄는 설정을 넣지 않습니다.
- 애플리케이션 코드는 수정하지 않습니다.
- 커밋, 푸시, PR 생성은 하지 않습니다. 변경 내용을 요약해 보여주고 사용자가 직접 커밋하게 합니다.
