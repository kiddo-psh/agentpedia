## 한 줄 요약

특별한 설정보다 **작업 습관**이 핵심입니다. 병렬로 돌리고, 계획하고, 기록하고, 검증합니다.

<KeyIdea title="가장 중요한 한 가지: 검증 루프">
Claude가 자기 작업을 확인할 방법을 주세요. 테스트 실행, bash 명령, 브라우저나 시뮬레이터에서 직접 확인하기 같은 것들입니다. 체르니는 이것만으로 결과물 품질이 2~3배 좋아진다고 말합니다.
</KeyIdea>

## 1. 병렬 세션

로컬 터미널에서 5개 정도, 웹에서 5~10개의 세션을 동시에 돌립니다. 로컬 세션마다 **별도 git 체크아웃**을 써서 서로의 변경이 충돌하지 않게 합니다. 팀원 중에는 worktree를 선호하는 사람도 많습니다.

## 2. 팀이 함께 키우는 CLAUDE.md

팀마다 `CLAUDE.md`를 git에 두고, Claude가 실수한 것이나 지켜야 할 규칙을 계속 추가합니다. 코드 리뷰에서 동료 PR에 Claude를 태그해 배운 점을 `CLAUDE.md`에 반영하게 하기도 합니다.

## 3. 계획 먼저, 구현은 한 번에

<Steps>
1. 계획 모드에서 계획이 마음에 들 때까지 대화로 다듬는다.
2. 자동 수락 모드로 바꾼다.
3. 대부분 한 번에 구현이 끝난다.
</Steps>

## 4. 반복 작업은 명령과 훅으로

- `.claude/commands/`에 커밋, PR 생성, 코드 단순화, 검증 같은 슬래시 명령을 둡니다.
- PostToolUse 훅으로 편집 후 포매터를 자동 실행해 CI 스타일 오류를 막습니다.
- 권한 확인을 통째로 끄지 않고, 안전한 명령(빌드, 테스트)만 미리 허용합니다.
