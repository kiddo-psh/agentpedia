# 목표: 내 코딩 에이전트의 격리가 지시가 아니라 강제 규칙인지 점검하기

2026년 7월 OpenAI의 내부 평가 사고에서는 인터넷 차단 샌드박스와 에이전트 간 통신 제한이 있었지만, 패키지 서버라는 허용된 구멍을 통해 격리가 우회됐다.
이 키트는 내 환경에서 "지시로만 있는 제한"과 "도구가 강제하는 제한"을 구분하고, 허용된 구멍을 목록으로 만든다. 기본은 **읽기 전용 점검**이다.

## 절대 지킬 것

- API 키, 토큰, 비밀번호, 개인 키의 **값을 출력하거나 보고서에 적지 않는다.** 설정 파일을 읽다 값이 보이면 이름과 줄 번호만 기록하고 값은 `***`로 가린다. `.env`와 키 파일은 열지 않고 존재 여부만 확인한다.
- 홈 디렉터리(`~/`)의 파일은 **읽기만** 한다. 고칠 필요가 있으면 사용자가 직접 실행할 명령을 보고서에 적는다.
- 격리가 뚫리는지 확인하려고 외부 접속, 우회, 취약점 시도를 하지 않는다. 도구의 공식 문서를 읽는 것은 예외이며, 문서 페이지 외의 곳에는 접속하지 않는다. 설정은 읽어서만 판단한다.
- 도구, 플러그인, 확장 프로그램을 설치하거나 삭제하지 않는다.

## 0. 맞는지 먼저 판단하기

아래를 확인한다. 해당하지 않으면 **아무것도 바꾸지 말고 멈춘 뒤** 이유를 알린다.

- 이 컴퓨터에서 Claude Code, Codex 같은 코딩 에이전트를 쓰고, 셸 실행이나 네트워크 접근을 허용한 설정이 있다.
- 현재 디렉터리가 사용자가 작업하는 레포다. 레포가 아니면 4-2단계(레포 설정 변경)는 건너뛴다. 보고서도 만들지 않고, 결과 표를 채팅으로만 보여준 뒤 멈춘다.

## 1. 현재 제한 목록 만들기 (읽기 전용)

있는 것만 확인한다. 없는 경로는 "없음"으로 적는다. 명령은 추측하지 말고 실제로 실행해 결과를 확인한다.

- 레포: `.claude/settings.json`, `.claude/settings.local.json`, `.mcp.json`, `.codex/`, `AGENTS.md`, `CLAUDE.md`
- 홈 (읽기만): `~/.claude/settings.json`, `~/.codex/config.toml`
- 항목별로 다음을 적는다.
  - 네트워크: 외부 접속을 허용하는 도구, 허용 도메인, 패키지 설치처럼 허용된 구멍
  - 비밀 파일: `.env`, 키 파일, 자격 증명 파일 읽기를 막는 규칙이 있는지
  - 위험 명령: 삭제, 강제 푸시, 권한 변경 같은 명령을 막는 규칙이 있는지
  - 샌드박스: 샌드박스 옵션이 켜져 있는지, 어떤 접근이 예외로 허용돼 있는지

## 2. 지시와 강제를 구분하기

각 제한에 유형을 붙인다. 판단이 확실하지 않으면 해당 도구의 공식 문서를 확인하고, 확인하지 못했으면 "미확인"으로 적는다.

- **강제**: 도구의 권한 차단 규칙이나 샌드박스 설정으로 실행 자체가 막힌다.
- **지시**: `AGENTS.md`, `CLAUDE.md`, 프롬프트 문장에만 적혀 있다. 에이전트가 따르길 기대할 뿐이다.
- **구멍**: 허용 목록에 있는 서비스나 명령. 임의의 요청을 대신 보내거나 파일을 쓸 수 있는지 함께 적는다.

비밀 파일이나 위험 명령이 "지시"로만 막혀 있으면 위험 항목으로 표시한다.

## 3. 계획을 보여주고 승인받기

다음을 보여주고 **사용자의 승인을 받은 뒤에만** 4단계를 진행한다.

- 1~2단계 결과 표 (항목, 위치, 유형, 위험 여부)
- 만들 보고서 파일: `docs/agent-isolation-audit.md`
- 레포 에이전트 설정에 추가할 차단 규칙과 샌드박스 옵션 목록 (없으면 "없음"). 이 레포가 쓰는 에이전트의 설정 형식에 맞춘다. 추가할 규칙은 비밀 파일 읽기와 위험 명령, 샌드박스 옵션에 한정한다. 네트워크 허용 목록은 바꾸지 않고 보고서에 권고만 적는다.
- 변경할 설정 파일은 정확한 경로 한 곳만 승인 목록에 적는다. 레포가 쓰는 에이전트가 하나면 그 도구의 공유 설정 파일(`.claude/settings.json` 또는 `.codex/config.toml`)을 고른다. 둘 이상이면 사용자에게 어느 파일인지 묻는다. 파일이 없으면 "새로 생성"이라고 표시한다. `.claude/settings.local.json`은 수정하지 않는다.
- 추가할 모든 키와 규칙 문법은 해당 도구의 공식 문서에서 확인한 것만 쓴다. 확인하지 못한 항목은 설정에 넣지 않고 보고서에 "미확인, 권고"로 적는다. 승인 목록에는 파일에 들어갈 JSON/TOML 조각을 그대로 보여준다.
- 주의: 샌드박스를 켜면 평소 쓰던 일부 명령이 막힐 수 있다.

## 4. 승인된 범위만 적용하기

### 4-1. 보고서 작성

- `docs/agent-isolation-audit.md`를 만든다. 점검 날짜, 항목 표, 위험 항목별 권장 조치, 홈 디렉터리 항목은 사용자가 직접 실행할 명령을 담는다. 값은 적지 않는다. 보고서 끝에 설정을 되돌리는 방법을 적는다.

### 4-2. 레포 설정 변경

- 수정할 설정 파일이 git에 추적되지 않으면(`git ls-files --error-unmatch <파일>`로 확인) 그 파일은 수정하지 않는다. 변경 내용은 보고서에 권고로만 적고, 사용자에게 직접 적용하도록 안내한다. 새로 만드는 파일은 이 규칙의 대상이 아니다.
- 승인한 차단 규칙과 샌드박스 옵션만 레포 설정에 추가한다. 다른 설정은 건드리지 않는다.

## 5. 실행해서 확인하기

- 수정한 설정 파일이 올바른 JSON 또는 TOML인지 파서로 확인한다. 예: `node -e "JSON.parse(require('fs').readFileSync('.claude/settings.json','utf8'))"`, TOML은 `python -c "import tomllib,sys;tomllib.load(open(sys.argv[1],'rb'))" .codex/config.toml`
- 추가한 규칙이 실제로 적용되는지 확인할 방법을 사용자에게 안내한다. Claude Code는 `/permissions`, Codex는 해당 설정 조회 명령으로 규칙이 읽혔는지 확인하게 한다. 직접 우회를 시도해 보지 않는다.
- 보고서와 수정한 설정 파일에 키·토큰 값이 들어가지 않았는지 `grep -nEi -e '(^|[^a-z])sk-[a-z0-9]{16,}|ghp_[A-Za-z0-9]{20,}|github_pat_|xox[bp]-|AKIA[0-9A-Z]{12,}|Bearer +[A-Za-z0-9._-]{16,}|-----BEGIN' docs/agent-isolation-audit.md <수정한 설정 파일>`로 확인한다. `grep`이 없으면 `Select-String -Pattern '<같은 패턴>' -Path <파일들>`을 쓴다. 결과가 없어야 통과이며, 걸리면 값을 `***`로 가린 뒤 다시 실행한다.
- `checklist.md`의 항목을 하나씩 점검하고 결과를 보고한다.
