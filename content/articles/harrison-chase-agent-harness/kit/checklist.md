# 점검 체크리스트

## 0. 중단 조건
- [ ] 코딩 에이전트 설정이나 검증 명령이 없어 맞지 않아 멈췄다면, 이 목록의 나머지 항목은 해당 없음이고 멈춘 이유만 보고했다.

## 컨텍스트 공급
- [ ] `CLAUDE.md`, `AGENTS.md`, `.claude/`, `.codex/`, `.cursor/` 등 에이전트가 항상 읽는 고정 컨텍스트 파일을 모두 적었다.
- [ ] 작업 중 필요할 때 읽게 하는 동적 컨텍스트(문서 경로, 스킬, MCP)를 적었다.
- [ ] 고정 컨텍스트의 지시가 실제 레포 구조와 맞는지 확인했다.

## 검증 루프
- [ ] 실행해도 파일이 바뀌지 않는 테스트, 린트, 타입 검사 명령은 실제로 실행해 결과를 확인했고, 추측한 명령은 없다. 파일을 쓰는 빌드와 상태를 바꾸는 명령은 실행하지 않고 보고서에 "미실행"으로 적었다.
- [ ] 검증 명령이 고정 컨텍스트에 적혀 있어 에이전트가 스스로 실행할 수 있다.
- [ ] `CLAUDE.md` 또는 `AGENTS.md`에 새로 추가한 검증 명령을 다시 실행해 성공을 확인했다(추가하지 않았다면 해당 없음).
- [ ] 실행했지만 실패한 명령은 "동작하지 않음"으로, 실행하지 않은 명령은 "미실행"으로 구분해 적었다.
- [ ] 과제별 평가나 벤치마크가 있는지 찾아 위치와 실행 명령을 적었고, 지연·토큰·비용을 재는지도 적었다. 없으면 "없음"으로 적고 새로 만들지 않았다.

## 트레이스와 실패 기록
- [ ] 에이전트의 도구 호출과 실행 기록을 어디서 볼 수 있는지 적었다.
- [ ] 실패 사례를 남길 위치(`docs/agent-failures.md`)가 있거나, 없는 이유를 적었다.

## 변경
- [ ] 보고서, 검증 명령 추가, 실패 기록 템플릿을 각각 따로 승인받았고 승인받지 않은 항목은 건너뛰었다.
- [ ] 보고서에 점검 날짜, 고정·동적 컨텍스트, 검증 명령과 실행 결과(실행/미실행/동작하지 않음), 평가·벤치마크 유무, 트레이스 확인 위치, 빠진 곳과 권장 조치가 모두 있다(만들었다면).
- [ ] `docs/agent-failures.md` 템플릿에 날짜, 증상, 에이전트가 받은 컨텍스트, 원인, 고친 곳 칸이 있다(만들었다면).
- [ ] 기존 문서를 덮어쓰지 않았다.
- [ ] 승인 전 명령 실행 전후의 `git status --short` 결과가 같았다. 달랐다면 새로 생기거나 바뀐 파일을 되돌리지 않고 보고했다.
- [ ] 2단계에서 기록한 시작 시점 `git status --short`와 비교했을 때, 새로 생기거나 바뀐 파일이 3단계에서 승인한 파일(보고서, `CLAUDE.md` 또는 `AGENTS.md` 하나, `docs/agent-failures.md`, 날짜 접미사 파일 포함)뿐이다.
- [ ] 이번에 만들거나 수정한 모든 파일에 `sk-`, `ghp_`, `-----BEGIN` 패턴이 없다.
- [ ] 기존 코드 로직, 훅, 미들웨어, 홈 디렉터리 설정은 수정하지 않았다.
- [ ] 외부 서비스 가입이나 도구 설치, `git commit` 등 git 기록을 바꾸는 명령을 하지 않았다.
