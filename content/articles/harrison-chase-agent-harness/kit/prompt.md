# 목표: 내 에이전트 설정의 컨텍스트 공급과 검증 루프 점검하기

해리슨 체이스의 인터뷰를 다룬 2026년 8월 Saytrace 요약은 에이전트를 모델, 하네스, 컨텍스트로 나누고, 에이전트 실패가 모델 능력 부족보다 모델에 공급된 컨텍스트의 질이 낮아서 생기는 경우가 많다고 설명한다(2026년 8월 공개 요약 기준이며 이후 바뀌었을 수 있다). Saytrace는 요약이 직접 인용이 아니라고 밝혔고, 체이스의 직접 발언은 확인되지 않았다. 이 키트는 이 레포의 에이전트 설정에 컨텍스트 공급과 검증 장치가 있는지 점검해 보고서로 남기고, 승인한 경우에만 검증 명령과 실패 기록 템플릿을 추가한다. 기본은 **읽기 전용 점검**이다.

## 절대 지킬 것

- 기존 코드 로직, 에이전트 훅, 미들웨어 구현은 수정하지 않는다.
- 외부 서비스에 가입하거나 트레이싱 도구를 설치하지 않는다.
- 홈 디렉터리(`~/`)의 전역 설정은 고치지 않는다. 필요하면 사용자가 직접 할 일을 보고서에 적는다.
- API 키, 토큰 값은 읽어서 출력하거나 파일에 적지 않는다.
- `git commit` 등 git 기록을 바꾸는 명령은 쓰지 않는다.

## 0. 맞는지 먼저 판단하기

아래에 해당하지 않으면 **아무것도 바꾸지 말고 멈춘 뒤** 이유를 알린다.

- 이 레포에서 코딩 에이전트를 쓴다. (`CLAUDE.md`, `AGENTS.md`, `.claude/`, `.codex/`, `.cursor/` 중 하나 이상으로 확인한다.)
- 테스트, 린트, 빌드 중 실행 가능한 검증 명령이 하나 이상 있다.

## 1. 컨텍스트 공급 점검 (읽기 전용)

- **고정 컨텍스트**: 에이전트가 항상 읽는 파일(`CLAUDE.md`, `AGENTS.md`, `.cursor/rules` 등)과 그 안의 핵심 지시를 정리한다.
- **동적 컨텍스트**: 작업 중 필요할 때 읽게 하는 것(`docs/`의 문서, 스킬, MCP 서버)을 정리한다.
- 고정 컨텍스트의 지시가 실제 레포와 어긋나는 곳(없는 경로, 바뀐 명령)을 표시한다.

## 2. 검증 루프 점검 (읽기 전용)

- `package.json`, `Makefile`, CI 설정 등에서 테스트, 린트, 빌드 명령 후보를 찾는다.
- 명령을 실행하기 전에 `git status --short` 결과를 기록한다.
- 명령은 추측하지 말고, 파일을 쓰지 않는 린트, 테스트, 타입 검사만 실제로 실행해 동작하는지 확인한다. 테스트가 DB나 외부 서비스를 호출하거나 파일을 쓸 것으로 보이면 실행하지 않고 "미실행"으로 적는다. 상태를 바꾸는 명령(배포, 마이그레이션, 삭제, 파일을 쓰는 빌드, `--fix`나 `--update` 같은 자동 수정 옵션)은 실행하지 않는다. 실행한 뒤 `git status --short`를 다시 실행해 실행 전 결과와 비교한다. 새로 생기거나 바뀐 파일이 있으면 되돌리지 말고 사용자에게 보고한다.
- 각 명령이 고정 컨텍스트에 적혀 있는지 확인한다.
- 과제별 평가나 벤치마크(eval 스크립트, 회귀 테스트 세트)가 레포에 있는지 찾고, 있으면 위치와 실행 명령을 적는다. 정확도 외에 지연·토큰·비용을 재는지도 적는다. 없으면 "없음"으로 적는다(만들지 않는다).
- 에이전트의 도구 호출과 실행 기록을 어디서 볼 수 있는지 적는다. 모르면 "확인하지 못함"으로 적는다.

## 3. 계획을 보여주고 승인받기

다음을 보여주고 **사용자의 승인을 받은 뒤에만** 4단계를 진행한다. 보고서, 검증 명령 추가, 실패 기록 템플릿 세 항목을 각각 따로 승인받고, 승인되지 않은 항목은 건너뛴다.

- 1~2단계 결과 요약 표 (항목, 위치, 상태, 빠진 곳)
- 만들 보고서: `docs/agent-harness-audit.md`
- 검증 명령을 넣을 파일 하나와 추가할 명령 (실제로 실행해 확인한 것만). `CLAUDE.md`가 `AGENTS.md`를 import하면 `AGENTS.md`에 넣는다. 둘 다 없으면 파일을 새로 만들지 말고 보고서에 권장 내용만 적는다.
- 실패 사례를 남길 `docs/agent-failures.md` 템플릿을 만들지 여부
- 이미 존재하는 `docs/agent-harness-audit.md`, `docs/agent-failures.md`가 있으면 덮어쓰지 말고 그 사실을 알린다. 승인받은 경우에만 `-YYYY-MM-DD`를 붙인 새 파일(예: `docs/agent-harness-audit-2026-11-12.md`)로 쓴다.

## 4. 승인된 범위만 적용하기

- 승인한 경우에만 `docs/agent-harness-audit.md`를 만든다. 점검 날짜, 고정·동적 컨텍스트 목록, 검증 명령과 실행 결과, 평가·벤치마크 유무, 트레이스(도구 호출·실행 기록)를 볼 수 있는 곳, 빠진 곳과 권장 조치를 담는다.
- 승인한 경우에만 3단계에서 정한 기존 파일(`CLAUDE.md` 또는 `AGENTS.md`)에 검증 명령을 추가한다. 새 파일은 만들지 않고, 기존 내용은 지우지 않는다.
- 승인한 경우에만 `docs/agent-failures.md`에 날짜, 증상, 에이전트가 받은 컨텍스트, 원인, 고친 곳 칸이 있는 템플릿을 만든다.

## 5. 실행해서 확인하기

- 추가한 검증 명령을 다시 실행해 동작을 확인한다.
- 이번에 만들거나 수정한 모든 파일(`git diff`와 새 파일)에 키나 토큰 값이 들어가지 않았는지 `sk-`, `ghp_`, `-----BEGIN` 패턴을 grep으로 찾는다.
- `checklist.md`의 항목을 하나씩 점검하고 결과를 보고한다.
