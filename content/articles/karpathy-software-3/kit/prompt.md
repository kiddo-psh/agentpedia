# 목표: 에이전트가 클릭 없이 이 레포를 다루고, 작은 단위로 검증하며 일하게 만들기

안드레 카파시는 2025년 6월 YC AI Startup School 강연에서 두 가지를 말했습니다.
문서가 "클릭하세요"라고 말하면 에이전트는 그 일을 할 수 없으니 문서를 바꿔야 한다는 것,
그리고 AI에게는 작은 단위로 맡기고 사람이 빠르게 검증하는 루프를 유지해야 한다는 것입니다.
이 레포에 그 두 가지를 적용합니다.

## 0. 먼저 맞는지 판단하기

- README, `docs/`, `CONTRIBUTING.md` 같은 문서를 먼저 읽습니다.
- 다음 중 하나라도 해당하면 아무것도 바꾸지 말고 이유를 설명한 뒤 멈춥니다.
  - 사람이 따라 하는 설치·설정·실행 문서가 없다.
  - 문서에 클릭, 화면 이동, 대시보드 설정 같은 사람 전용 지시가 하나도 없다. (이 경우 진입 문서만 필요한지 사용자에게 묻습니다.)
  - 빌드나 테스트 명령을 찾을 수 없거나, 찾았더라도 비밀 값·외부 계정 없이는 로컬에서 실행할 수 없다.

## 1. 계획을 보여주고 승인받기

이 단계까지는 파일을 읽기만 하고 명령을 실행하지 않습니다.
파일을 바꾸거나 명령을 실행하기 전에 아래 내용을 정리해 보여주고, 사용자의 승인을 받은 뒤에만 진행합니다.

- 찾은 사람 전용 지시 목록 (파일, 위치, 원문)
- 각 지시를 바꿀 명령 후보, 또는 바꿀 수 없는 이유
- 진입 문서(`AGENTS.md` 또는 `CLAUDE.md`)에 넣을 명령과 작업 규칙
- 확인을 위해 실행할 명령 목록과, 각 명령이 바꿀 수 있는 로컬 파일(예: lockfile, 빌드 산출물)

## 2. 할 일 (이 세 가지만)

1. **문서의 "클릭" 걷어내기**: README, `docs/`, `CONTRIBUTING.md`에서 "클릭", "화면에서 선택", "대시보드에서 설정" 같은 지시를
   같은 일을 하는 셸 명령, 스크립트, CLI 호출로 고쳐 씁니다.
   바꿀 수 없는 단계(외부 서비스 콘솔에서만 가능한 설정 등)는 그대로 두고, 왜 바꿀 수 없는지 그 자리에 한 줄로 적습니다.
2. **에이전트 진입 문서**: 레포 루트에 `AGENTS.md`와 `CLAUDE.md`가 모두 없으면 `AGENTS.md` 초안을 만듭니다.
   하나라도 있으면 새 파일을 만들지 말고 있는 파일에 빠진 명령만 보강합니다(둘 다 있으면 둘 다 확인).
   빌드, 테스트, 실행 명령을 담습니다.
   끝나지 않는 실행 명령(dev 서버 등)은 준비 완료 메시지나 로컬 주소 응답을 확인한 뒤 종료하고, 그 확인 방법을 명령 옆에 적습니다.
3. **작업 규칙**: 같은 진입 문서에 다음 규칙을 적습니다.
   "변경은 작게 나누어 한다. 단계마다 위의 테스트·빌드 명령을 실행해 검증한 뒤 다음 단계로 간다."

## 3. 지켜야 할 것

- 추측한 명령은 쓰지 않습니다. 레포에 실제로 있는 명령만, 직접 실행해서 성공을 확인한 뒤 문서에 넣습니다.
  실행 결과(성공·실패)를 사용자에게 보여줍니다.
- 외부 서비스, 원격 저장소, 배포 환경, 계정 상태를 바꾸는 명령(배포, 환경변수 등록, 결제·인증 설정, push 등)은 확인용으로도 실행하지 않습니다.
  이런 단계는 문서에서 바꾸지 않고 "외부 상태를 바꾸는 명령이라 실행해 확인하지 않았습니다"라고 이유만 적습니다.
  실행 대상은 로컬에서 끝나는 빌드·테스트·실행 명령으로 한정합니다.
- 문서를 바꾸기 전에 테스트를 한 번 실행해 기준 결과를 기록합니다. 기준 테스트가 이미 실패하면 고치지 말고 결과를 보여준 뒤 진행 여부를 묻습니다.
- 명령 실행으로 문서가 아닌 추적 파일(lockfile, 생성 파일 등)이 바뀌면 그 변경은 되돌리고 사용자에게 알립니다.
- 애플리케이션 코드는 수정하지 않습니다. 바꾸는 파일은 문서와 진입 문서뿐입니다.
- 외부 서비스 콘솔의 설정을 바꾸거나 계정을 만들지 않습니다.
- 변경은 작게 나누어 진행하고, 사용자가 diff를 확인하게 합니다.
