소프트웨어는 70년 가까이 거의 안 바뀌다가 최근에 두 번 바뀌었습니다.
Andrej Karpathy가 2025년 6월 17일 강연을 이렇게 열었습니다.
자리는 샌프란시스코의 AI Startup School입니다.
주최는 Y Combinator이고, 객석은 곧 입사할 학생이 많았습니다.

소개는 전 테슬라 AI 디렉터였습니다.
OpenAI 창립 멤버였고, 테슬라 오토파일럿의 컴퓨터 비전 팀을 이끌었습니다.
스탠퍼드에서는 첫 딥러닝 강좌 CS231n을 설계하고 주 강사를 맡았습니다.
본인 홈페이지에 적힌 경력입니다.

## 완벽한 시연도 10년이 걸린다

업계는 올해를 에이전트의 해라 불렀습니다.
사람 손 없이 AI가 일을 끝내 주리라는 기대입니다.
Karpathy는 이 말을 걱정합니다.
2013년, 웨이모에 있던 친구 제안으로 팔로알토에서 자율주행차를 탔습니다.
30분 동안 개입이 없었고 주행은 완벽했으나, 12년 뒤 2025년에도 안 풀렸습니다.
그래서 2025년은 에이전트의 해가 아닙니다.
지금은 에이전트의 10년입니다.
이 10년은, 시연이 완벽해도 문제가 남은 시간입니다.

<KeyIdea title="로봇이 아니라 슈트를 만든다">
아이언맨 슈트는 능력을 키우는 도구이자 스스로 움직이는 에이전트입니다.
지금은 <Term id="partial-autonomy">부분 자율</Term> 제품의 때입니다.
화려한 데모보다 이쪽입니다.
확인용 화면과 자율성 슬라이더가 있고, 슬라이더는 천천히 오른쪽으로 갑니다.
</KeyIdea>

## 소프트웨어 3.0은 영어로 쓴다

소프트웨어는 세 가지입니다.

- **Software 1.0**: 사람이 컴퓨터를 위해 직접 쓰는 코드입니다.
- **Software 2.0**: 신경망 가중치입니다. 데이터와 최적화기로 만들고, 2017년 블로그의 이름입니다.
- **<Term id="software-3-0">Software 3.0</Term>**: 프롬프트가 LLM을 움직이는 프로그램이고, 영어로 씁니다. 신경망 자체를 프로그램으로 다루게 됐습니다.

감정 분류는 세 갈래로 됩니다.

- 파이썬 코드
- 신경망 학습
- 예시 몇 개를 넣은 프롬프트
설명란 메모도 같습니다.
LLM은 새 종류의 컴퓨터이고 영어로 프로그래밍합니다.
세 방식이 나란히 남기만 하지는 않습니다.
테슬라에서 신경망이 커지며 같은 기능의 C++ 코드(1.0)는 지워졌습니다.
Software 2.0이 오토파일럿을 먹어 들어갔고, 지금은 Software 3.0이 다시 먹어 들어갑니다.
개발자는 셋을 다 다루고, 문제마다 방식을 골라야 합니다.

## LLM은 1960년대 컴퓨터와 닮았다

비유는 셋입니다.

- **유틸리티**: 연구소는 전력망처럼 큰돈으로 모델을 학습합니다. 운영비로 API 지능을 공급하고 쓴 만큼 받습니다. 사용자는 낮은 지연과 높은 가동률을 요구합니다. 일정한 품질도 요구합니다. OpenRouter는 여러 LLM API를 바꿔 쓰는 전환 스위치입니다. 모델이 멈추면 지능의 전압 강하가 옵니다.
- **팹**: 큰 투자와 오랜 축적이 필요합니다. 연구 비밀도 한곳에 모입니다. 자체 칩 TPU로 학습하는 구글은 공장을 가진 인텔과 비슷합니다. 엔비디아 GPU만 사면 설계만 하는 회사와 비슷합니다.
소프트웨어는 쉽게 바뀌어 비유가 약합니다.
- **운영체제**: 가장 잘 맞습니다. 폐쇄형은 Windows나 macOS와 같고, 메타 Llama는 Linux에 가까워질 수 있습니다. LLM은 CPU, <Term id="context-window">컨텍스트 창</Term>은 메모리입니다.

<Quote source="yc-talk" at="6:06">
Many historical analogies apply - imo we are computing circa ~1960s.
</Quote>

비유가 여럿 맞고, 컴퓨팅은 대략 1960년대입니다.
연산이 비싸 클라우드에 모이고, 사용자는 시간을 나눠 쓰는 얇은 클라이언트입니다.
1960년대 시분할과 닮았습니다.
Karpathy는 개인용 컴퓨터 혁명에 견줄 변화가 아직 오지 않았다고 봤습니다.
초기 신호는 Mac mini이고, 책상 위에서 LLM을 돌리기 좋은 기기입니다.
텍스트 대화는 터미널로 운영체제를 쓰는 느낌이고, 누구나 쓰는 GUI는 없습니다.
보통 기술은 정부와 기업이 먼저 쓰고 소비자에게 내려옵니다.
LLM은 소비자가 먼저 썼습니다.

### 쉽게 틀려서 사람이 확인한다

LLM은 사람을 확률로 흉내 내고, 표현은 people spirits, 사람 혼령에 가깝습니다.
어떤 일은 사람보다 잘합니다.
어떤 일은 쉽게 틀립니다.
컨텍스트가 지워지면 다 잊습니다.
예는 기억을 못 간직하는 「메멘토」와 「첫 키스만 50번째」입니다.
남의 말을 쉽게 믿습니다.
<Term id="prompt-injection">프롬프트 인젝션</Term>에도 넘어갑니다.
그래서 결과를 확인하는 슈트가 필요합니다.

## 부분 자율 앱은 검증을 빨리 돌린다

첫 예는 Cursor이고, 공통점은 넷입니다.

1. 앱이 맥락을 대신 관리합니다.
2. 여러 LLM 호출을 엮습니다.
   - 임베딩
   - 채팅
   - diff 적용 모델
3. 확인용 화면이 있습니다. 바뀐 곳은 빨간색·초록색 diff이고, 단축키로 수락하거나 거절합니다.
4. 자율성 슬라이더가 있습니다. 위치는 작업 복잡도에 따라 정합니다.
   - 탭 자동완성
   - Cmd+K는 코드 일부
   - Cmd+L은 파일 하나
   - Cmd+I는 레포 전체

둘째 예 Perplexity는 출처를 보여 답을 확인하게 합니다.
이 슬라이더의 단계는 셋입니다.

- 빠른 검색
- 리서치
- 딥 리서치
속도가 중요합니다.
만들고 검증하는 한 바퀴를 빨리 돌려야 합니다.
사람은 글보다 색과 그림을 빨리 보고, 색으로 표시한 화면이 확인을 당깁니다.
한 번에 맡기는 범위는 좁혀, 멀리 못 가게 붙잡습니다.
1,000줄 diff는 소용없습니다.
검증하는 사람이 병목이라 작게 나눕니다.
프롬프트가 구체적일수록 검증이 한 번에 통과하고, 같은 자리를 덜 맴돕니다.
교육도 같습니다.
강좌를 만드는 앱과 학생에게 가르치는 앱을 나누고, 그 사이 강좌가 확인용 중간 결과입니다.
AI는 그 밖으로 나가지 않습니다.

## 클릭 지시를 명령으로 바꾼다

영어를 하면 누구나 프로그래머라고 Karpathy는 말합니다.
메뉴 사진에 음식 그림을 붙이는 앱입니다.
이름은 MenuGen이고, <Term id="vibe-coding">바이브 코딩</Term>으로 만들었습니다.
코드는 금방 끝났고, 일주일이 더 걸린 일은 다음입니다.

- 인증
- 결제
- 도메인 연결
- Vercel 배포

그동안 클릭만 했습니다.
인증 서비스 Clerk 문서는 URL과 드롭다운 클릭을 안내했습니다.
정보의 옛 주체는 사람(GUI)이었습니다.

프로그램(API)도 주체였습니다.

에이전트가 세 번째입니다.
설명란의 Build for agents는 에이전트를 위해 만들라는 말입니다.
마크다운으로 옮기기는 쉽고, 문제는 클릭하라는 문장입니다.
문서 내용 자체를 바꿉니다.

- robots.txt처럼 LLM용 소개 파일 <Term id="llms-txt">`llms.txt`</Term>를 둡니다.
- 문서도 마크다운으로 씁니다. Vercel과 Stripe가 먼저 바꿨습니다.
- 클릭을 같은 일의 명령으로 바꿉니다. 당시 Vercel은 클릭을 `curl`로 바꾸던 중이었습니다.
- Anthropic의 <Term id="mcp">MCP</Term>는 대화 프로토콜입니다.
에이전트와 직접 대화합니다.
MCP는 AI 앱을 외부 도구·데이터와 잇는 오픈소스 표준입니다.

gitingest와 DeepWiki도 있습니다.
GitHub 주소 일부만 바꿉니다.
레포가 LLM이 읽기 좋은 글이나 문서가 됩니다.
2025년 6월에도 LLM은 화면을 클릭할 수 있었습니다.
그래도 문서와 도구가 에이전트 쪽으로 바뀔 가치가 있습니다.
클릭은 비싸고 더 어렵습니다.

## 바뀌지 않는 소프트웨어도 많다

Karpathy도 한계를 인정합니다.
많은 소프트웨어는 에이전트에 맞춰 바뀌지 않을 겁니다.
수는 많고 종류도 제각각입니다.
화면 클릭은 계속 필요합니다.
Cursor 단축키와 Vercel·Stripe 문서는 2025년 6월 강연의 예입니다.
지금은 다를 수 있습니다.
남은 것은 방향입니다.
앞으로 10년 동안 슬라이더는 왼쪽에서 오른쪽으로 갑니다.
레포에서 얼마나 올릴지는, 클릭 없이 검증하는 범위에 달렸습니다.
