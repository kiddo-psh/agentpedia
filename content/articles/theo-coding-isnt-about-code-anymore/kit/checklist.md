# 점검 체크리스트

## 환경
- [ ] CI 설정 위치, job/stage 연결, timeout, 캐시 키·경로를 적었다(없으면 없다고 적었다).
- [ ] 테스트·린트·타입 검사 명령을 실제 설정 파일에서 읽어 적었다.
- [ ] 테스트 파일 개수와 종류를 적었다.
- [ ] 개발 서버 명령 이름만 적고 실행하지 않았다(또는 해당 없음).

## 실행
- [ ] 실행 전에 명령 목록과 부작용 여부를 보여 주고 승인받았으며, 승인받은 명령만 실행했다.
- [ ] 파일을 바꾸지 않는 명령만 실행했다.
- [ ] 각 명령의 걸린 시간과 성공 여부를 적었다.
- [ ] 시작과 끝의 `git status --short --ignored`를 비교했고, 무시 디렉터리 안 변경은 잡히지 않는다는 한계를 보고서에 적었다.
- [ ] 검증 명령도 CI도 없거나 git 레포가 아니면 아무것도 바꾸지 않고 멈췄다(해당 없음 가능).
- [ ] API 키·토큰 값을 출력하지 않았고 홈 디렉터리 전역 설정을 바꾸지 않았다.
- [ ] Claude Code 버전·플러그인 설정 장문을 쓰지 않았다.

## 변경
- [ ] 테스트, CI 설정, 빌드 스크립트를 삭제하거나 수정하지 않았다.
- [ ] 삭제 후보는 보고서에 근거만 적고 삭제 권고를 하지 않았다.
- [ ] 보고서와 지시 파일 변경은 사용자가 승인한 것만 했다.
- [ ] `git commit` 등 git 기록을 바꾸는 명령을 쓰지 않았다.

## 보고서
- [ ] 보고서가 이미 있으면 덮어쓰지 않고 날짜 붙은 새 파일로 썼다(해당 없음 가능).
- [ ] 보고서에 개발 서버는 실행하지 않아 속도를 재지 못했다고 적었다(또는 해당 없음).
- [ ] 보고서에 점검 날짜, CI 구성·timeout·캐시, 명령별 시간·결과, 테스트 규모가 들어 있다.
- [ ] 보고서에 빠진 곳, 느릴 수 있는 곳, 권장 조치가 들어 있다(테스트·CI 삭제 없음).
- [ ] 보고서·지시 파일 변경 전에 계획을 보여 주고 두 번째 승인을 받았다.
- [ ] 지시 파일에는 기존 내용을 지우지 않고 한 줄만 덧붙였다(덧붙이지 않았다면 해당 없음).
- [ ] 덧붙인 명령은 이번 실행에서 실제로 돌려 성공한 것이다(덧붙이지 않았다면 해당 없음).
- [ ] 대상 파일이 불명확하면 건너뛰고 보고서에 이유를 적었다.
- [ ] 실행으로 새로 생긴 캐시·산출물을 되돌리지 않고 보고서에 적었다(없으면 해당 없음).
