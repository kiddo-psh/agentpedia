# 점검 체크리스트

## 표본
- [ ] 최근 머지 PR 또는 커밋을 최대 10개만 골랐고, 없는 건수를 지어내지 않았다.
- [ ] 개수와 경로는 `gh pr list` 또는 `git log`를 실제로 실행해 확인했다.

## 분류
- [ ] 각 항목에 Ship, Show, Ask 중 하나와 근거가 있다.
- [ ] 각 diff를 `gh pr diff` 또는 `git show`로 읽었다. 읽지 못한 변경은 Ask이고 Ship이 아니다.
- [ ] 파일 이름에 조각이 없어도, diff가 인증 검사나 민감 데이터 노출을 바꾸면 Ask다. 비밀 값 때문에 그 판단을 못하면 Ask다.
- [ ] 인증·민감 데이터로 둔 경로는 Ask이고, 그 조각 목록을 사용자가 승인했다.
- [ ] 다른 사람 리뷰 후 머지 PR 두 개, 최근 30일 기여 중 하나라도 확인하지 못하면 Ship으로 적지 않았다. 근거가 없는 항목을 Show로 올리지 않고 Ask로 두었다.
- [ ] 고객에게 말하는 내용처럼 저장소 밖에서만 알 수 있는 목적은 "확인하지 못함"이다.

## 보고서
- [ ] 보고서가 추천이며 설정을 바꾸지 않았다고 적혀 있다.
- [ ] 도장 감소나 리뷰 품질을 측정값처럼 적지 않았다.
- [ ] 비밀 값 패턴(`sk-`, `ghp_`, `-----BEGIN`)이 없다.

## 변경
- [ ] 파일을 쓰기 전에 사용자의 승인을 받았다.
- [ ] `git status --short -uall`의 새 줄이 보고서 파일 하나뿐이고, 추적 파일의 diff 해시는 시작과 같다.
- [ ] 브랜치 보호, PR 댓글, 승인, 머지, `git commit`을 하지 않았다.
