# 점검 체크리스트

## 후보
- [ ] 후보를 3개 보여 주고 사용자가 한 건을 골랐다.
- [ ] 후보의 정의 위치를 파일과 줄 번호로 적었다.

## 증거
- [ ] 코드 안 사용처와, 문자열·설정·동적 호출로 쓰일 가능성을 확인했다.
- [ ] `git log`로 최근 변경 이력을 실제로 확인했다.
- [ ] 킬스위치나 장애 대응용일 가능성을 점검했다.
- [ ] 이슈·PR은 읽기 조회만 했고, 운영 로그·콘솔에는 접속하지 않고 사용자에게 위치를 물었다.
- [ ] 접근하지 못한 출처는 "확인하지 못함"으로 적었고, 추측으로 채우지 않았다.

## 보고서
- [ ] 확인하지 못한 것과 사람이 판단할 질문이 들어 있다.
- [ ] 삭제 범위는 제안으로만 적었고 실제로 지우지 않았다.
- [ ] 비밀 값 패턴(`sk-`, `ghp_`, `-----BEGIN`)이 없음을 grep으로 확인했다.

## 변경
- [ ] 보고서를 쓰기 전에 사용자의 승인을 받았다.
- [ ] `git status --short -uall`의 새 줄이 보고서 파일 하나뿐이고, 추적 파일의 `git diff` 해시가 시작 때와 같다.
- [ ] 같은 이름의 파일이 있었다면 덮어쓰지 않고 승인받은 새 이름을 썼다. `docs/` 폴더를 새로 만들었다면 계획에 적고 승인받았다.
- [ ] 브랜치, 커밋, PR을 만들지 않았다.
