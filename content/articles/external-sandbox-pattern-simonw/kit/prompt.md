# 목표: 떠 있는 외부 샌드박스에 허용 목록 밖 요청을 시켜 실제 결과만 적기

Simon Willison의 외부 샌드박스는 에이전트를 호스트에 두고 코드만 게스트에서 실행한다. Codex 가이드는 게스트 네트워크가 기본으로 꺼져 있다고 적는다. 이 키트는 이미 떠 있는 루프백 서버에만 허용 목록 밖 요청을 한 번 시키고, 출력을 그대로 `docs/external-sandbox-probe.md`에 남긴다. 서버가 없으면 설치하지 않고 멈춘다.

## 절대 지킬 것

- 승인받기 전에는 파일을 만들거나 고치지 않는다.
- 샌드박스 서버, uv, 컨테이너, QEMU를 설치하거나 새로 띄우지 않는다. 클론하지 않는다.
- 호스트 신뢰 저장소에 인증서를 넣지 않는다. 비밀과 토큰 값을 출력하지 않는다.
- 허용 목록 밖 요청의 결과를 지어내지 않는다. 실행하지 않았으면 "실행 안 함"이라고 적는다.
- 검증 명령을 CLAUDE.md·AGENTS.md에 덧붙이지 않는다. 그건 Boris Cherny 키트 범위다.
- 애플리케이션 코드, 커밋, 푸시를 하지 않는다.

## 0. 맞는지 먼저 판단하기

루프백만 본다. `EXTERNAL_SANDBOX_API_URL`과 `http://127.0.0.1:8686`, `8687`, `8688`의 `/health`만 확인한다. 어느 쪽도 응답하지 않으면 이유를 설명한 뒤 여기서 멈춘다. 보고서를 만들지 않는다.

## 1. README가 말하는 연결을 한 줄로 적기

응답한 URL만 적는다. Claude Code는 셸 접두가 명령을 게스트로 보내고 Read/Edit는 호스트에 남는다는 점, Codex는 CLI 0.164.0 기준 문서이고 네트워크가 기본으로 꺼져 있다는 점만 [README](https://github.com/prime-radiant-inc/external-sandbox)와 대조해 한 줄씩 적는다. Pi 설정 절차는 이 저장소에 없으므로 "별도 저장소, 여기선 확인 안 함"이라고만 적는다.

## 2. 계획을 보여주고 승인받기

허용 목록에 없을 호스트 하나(예: `https://example.com`)와, 그 요청을 게스트 경유로 한 번만 보내겠다는 계획을 보여 준다. 승인 전에는 요청하지 않는다.

## 3. 승인 뒤에만 한 번 실행하고 파일을 만들기

승인한 경우에만 그 서버의 실행 API로 요청을 한 번 실행해서 상태 코드와 출력 앞부분을 그대로 옮긴다. 호스트에서 직접 그 호스트로 우회 요청하지 않는다. `docs/external-sandbox-probe.md`에 URL, README 한 줄, 실행한 명령, 출력을 적는다. 같은 이름의 파일이 있으면 덮어쓰지 말고 다른 이름을 제안한 뒤 고를 때까지 멈춘다. 만든 파일을 다시 읽어 출력이 실행 결과와 같은지 확인한다.
