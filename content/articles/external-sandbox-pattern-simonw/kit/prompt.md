# 목표: 떠 있는 외부 샌드박스에 허용 목록 밖 요청을 시켜 실제 결과만 적기

Simon Willison의 외부 샌드박스는 에이전트를 호스트에 두고 코드만 게스트에서 실행한다. Codex 가이드는 게스트 네트워크가 기본으로 꺼져 있다고 적는다. 이 키트는 이미 떠 있는 루프백 서버의 활성 allow를 읽은 뒤에만, 그 목록에 없는 호스트로 한 번 요청하고, 출력을 그대로 `docs/external-sandbox-probe.md`에 남긴다. 서버가 없거나 정책을 읽지 못하면 요청하지 않고 멈춘다.

## 절대 지킬 것

- 승인받기 전에는 파일을 만들거나 고치지 않는다.
- 샌드박스 서버, uv, 컨테이너, QEMU를 설치하거나 새로 띄우지 않는다. 클론하지 않는다.
- 호스트 신뢰 저장소에 인증서를 넣지 않는다. 비밀과 토큰 값을 출력하지 않는다.
- 허용 목록 밖 요청의 결과를 지어내지 않는다. 실행하지 않았으면 "실행 안 함"이라고 적는다.
- 활성 allow를 읽기 전에는 바깥 호스트를 고르지 않는다. 정책을 못 읽으면 요청하지 않고 "결론 없음"이라고 적는다.
- `X-Proxy-Token` 값, credential, secretEnv 값은 출력하지 않는다. allow의 origin만 적는다.
- 검증 명령을 CLAUDE.md·AGENTS.md에 덧붙이지 않는다. 그건 Boris Cherny 키트 범위다.
- 애플리케이션 코드, 커밋, 푸시를 하지 않는다.

## 0. 맞는지 먼저 판단하기

루프백만 본다. `EXTERNAL_SANDBOX_API_URL`과 `http://127.0.0.1:8686`, `8687`, `8688`의 `/health`만 확인한다. 어느 쪽도 응답하지 않으면 이유를 설명한 뒤 여기서 멈추고, 보고서를 만들지 않는다.

## 1. README가 말하는 연결을 한 줄로 적기

응답한 URL만 적는다. Claude Code는 셸 접두가 명령을 게스트로 보내고 Read/Edit는 호스트에 남는다는 점, Codex는 CLI 0.164.0 기준 문서이고 네트워크가 기본으로 꺼져 있다는 점만 [README](https://github.com/prime-radiant-inc/external-sandbox)와 대조해 한 줄씩 적는다. Pi 설정 절차는 이 저장소에 없으므로 "별도 저장소, 여기선 확인 안 함"이라고만 적는다.

## 2. 활성 allow를 읽고 계획을 보여 주기

프로토콜의 `GET /proxy`에서 `proxy-token` 메타를 읽고, 그 값을 `X-Proxy-Token`으로 넣어 `GET /proxy/api`만 호출한다. 응답의 `policy.allow`에 있는 origin만 적는다. 토큰과 credential 필드는 적지 않는다. 404·403이거나 본문을 정책으로 읽지 못하면 이유를 설명한 뒤 여기서 멈춘다. 요청은 보내지 않는다.

읽은 origin에 없는 호스트 하나를 고른다. 목록에 있는지 확인하지 않은 호스트는 고르지 않는다. 그 호스트로 게스트 경유 요청을 한 번만 보내겠다는 계획을 보여 준다. 승인 전에는 요청하지 않는다.

## 3. 승인 뒤에만 한 번 실행하고 파일을 만들기

승인한 경우에만 그 서버의 실행 API로 요청을 한 번 실행해서 상태 코드와 출력 앞부분을 그대로 옮긴다. 호스트에서 직접 그 호스트로 우회 요청하지 않는다. `docs/external-sandbox-probe.md`에 URL, README 한 줄, 읽은 origin, 고른 호스트, 실행한 명령, 출력을 적는다. 정책을 못 읽었으면 "결론 없음"만 적는다. 같은 이름의 파일이 있으면 덮어쓰지 말고 다른 이름을 제안한 뒤 고를 때까지 멈춘다. 만든 파일을 다시 읽어 출력이 실행 결과와 같은지, 토큰이 없는지 확인한다.
