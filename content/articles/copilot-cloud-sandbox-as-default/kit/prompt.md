# 목표: 로컬 전용과 클라우드 샌드박스 작업을 나누고 정책을 점검하기

2026년 10월 28일 GitHub는 연결된 Copilot 클라우드 경험을 정식 출시했고, **기본으로** 세션이 격리된 클라우드 샌드박스에서 돈다. 기사 claim은 **실행 장소가 노트북 연장이 아니라 팀 정책**이 된다는 것이다.
이 키트는 로컬에서만 돌릴 작업과 클라우드로 넘길 작업을 나누고, SSO·MCP 허용 목록·도구 승인·레포 제외 점검표를 `docs/copilot-cloud-policy.md`에 남긴다. 기본은 **읽기 전용 점검**이다. MCP 커넥터 인벤토리(github-verified-mcp-connectors)나 침해 흔적 점검(agent-tools-trust-boundary)은 하지 않는다.

## 절대 지킬 것

- 조직·엔터프라이즈 Copilot 정책 UI, `managed-settings.json`, Actions secrets를 **직접 수정하지 않는다.** 권고와 확인 절차만 적는다.
- 클라우드 세션을 대신 시작하거나, runner·환경 호스트를 등록·삭제하지 않는다.
- API 키·토큰 값을 읽거나 출력하지 않는다.
- `git commit` 등 git 기록을 바꾸는 명령은 실행하지 않는다.

## 0. 맞는지 먼저 판단하기

아래를 확인한다. 해당하지 않으면 **아무것도 바꾸지 말고 멈춘 뒤** 이유를 알린다.

- 팀이 GitHub Copilot을 쓰거나 도입을 검토한다. 또는 레포에 Copilot·에이전트·샌드박스 관련 문서·설정(`.github/`, `copilot-setup-steps.yml`, 에이전트 안내 등)이 있다.
- 사용자가 정책 보고서를 남길 권한이 있는 작업 레포다.

## 1. 단서 모으기 (읽기 전용)

추측하지 말고 파일·문서를 **실제로 열어** 확인한다.

- `copilot-setup-steps.yml`, self-hosted runner, Windows·특수 이미지, 사설 패키지 레지스트리, 로컬 전용 스크립트 언급
- `.mcp.json` 등 MCP가 있어도 **인벤토리 보고서까지는 만들지 않는다.** "클라우드에서도 쓸지 / 로컬 전용인지" 한 줄만 적고, 상세 분류는 github-verified-mcp-connectors 키트로 넘긴다.
- README·내부 문서에 적힌 "로컬에서만", "VPN 필요", "클라우드 에이전트 금지" 같은 문장

## 2. 작업 분류하기

표를 만든다.

- **로컬 전용 후보**: 사설 네트워크, 로컬 DB/시크릿 파일, 특수 하드웨어, 아직 클라우드 방화벽에 없는 호스트
- **클라우드 기본 후보**: 순수 레포 작업, 공개·허용된 의존성, 병렬 에이전트 실험
- **Actions 환경 후보**: `copilot-setup-steps.yml`, self-hosted runner, Windows 등 Changelog·문서가 Actions를 요구하는 경우

각 행에 근거 파일 경로를 붙인다. 근거가 없으면 "미확인"으로 두고 사용자에게 묻는다.

## 3. 정책 점검표 채우기

조직 관리자가 아니면 UI를 추측해 채우지 않는다. 확인 못 하면 **미확인**과 확인할 위치만 적는다. 공식 문서 URL은 작성 시점 기준으로 다시 연다.

| 항목 | 확인 내용 |
|---|---|
| Copilot in the cloud | 정책이 켜져 있는지, 레포 제외가 있는지 |
| SSO | 조직 레포 세션에 SSO가 필요한지 |
| MCP 허용 목록 | managed-settings / 정책에 allowlist·denylist가 있는지 |
| 도구 승인 | 승인 없이 도구를 실행하도록 두지 않았는지 |
| 레포 제외 | 민감 레포가 클라우드에서 빠져 있는지 |
| 과금 | 클라우드 샌드박스 과금 시작일·Actions entitlement 공유를 팀이 아는지 (Changelog: 2026-11-23) |

## 4. 계획을 보여주고 승인받기

다음을 보여주고 **사용자의 승인을 받은 뒤에만** 5단계를 진행한다.

- 작업 분류표와 정책 점검표 초안
- 만들 파일: `docs/copilot-cloud-policy.md`
- 승인 시에만 추가할 한 줄 안내(대상 파일, 문구). 대상 파일이 없으면 보고서에만 싣는다.

## 5. 승인된 범위만 적용하기

- `docs/copilot-cloud-policy.md`를 만든다.
- 승인한 한 줄 안내만 기존 문서에 추가한다. 없으면 건너뛴다.

## 6. 실행해서 확인하기

- 보고서 파일이 생겼는지 확인한다.
- 추가한 문서가 있으면 해당 줄이 들어갔는지 파일을 다시 읽어 확인한다.
- 보고서에 비밀 값 패턴이 없는지 grep을 **실행해** 확인한다.
- `checklist.md` 항목을 하나씩 점검하고 결과를 보고한다.
