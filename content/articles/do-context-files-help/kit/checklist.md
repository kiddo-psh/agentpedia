# 점검 체크리스트

## 시작 전
- [ ] 해당하지 않는 레포(git 저장소 아님, 컨텍스트 파일 없음 또는 비어 있지 않은 줄이 합쳐 10줄 미만, 대상 파일에 미커밋 변경 또는 git 무시 대상, `docs/context-file-audit.md` 이미 존재)에서는 아무것도 바꾸지 않고 멈췄습니다.

## 읽기
- [ ] 레포 루트와 하위 폴더의 `CLAUDE.md`, `AGENTS.md`를 모두 찾았습니다.
- [ ] 각 줄을 A(코드로 알 수 있음), B(코드만으로는 알 수 없음), C(판단 불가)로 나눴습니다.
- [ ] A로 분류한 줄은 파일을 열거나 상태를 바꾸지 않는 명령으로 직접 확인했습니다. 추측한 명령은 없습니다.
- [ ] `@경로` import 줄과 자동 생성 블록은 삭제 후보에 올리지 않았습니다.
- [ ] 대상이 아닌 import 파일은 읽기만 했고 수정하지 않았습니다.
- [ ] B로 분류한 줄마다 이어진 실제 실패가 있는지 사용자에게 물었습니다.
- [ ] 코드와 어긋난 줄과 자동 생성 블록은 C로 분류해 삭제 후보에 올리지 않았고, 어긋난 점은 계획 보고에 적었습니다.
- [ ] 빌드, 테스트, 설치, 배포, 마이그레이션 명령을 실행하지 않았습니다.
- [ ] 사용자가 삭제를 명시하지 않은 B 줄은 모두 유지했습니다.

## 승인
- [ ] 삭제 후보와 근거를 보여주고 사용자의 승인을 받았습니다.
- [ ] 승인한 줄만 지웠습니다.
- [ ] 삭제 후보가 0줄이거나 승인한 줄이 없으면 파일을 만들지 않고 멈췄습니다.

## 변경
- [ ] `git diff`에서 삭제된 비어 있지 않은 줄 수가 승인한 줄 수와 같고, 삭제된 줄 하나하나가 승인 목록에 있습니다.
- [ ] 새 규칙이나 설명을 추가하지 않았습니다. `git diff`에 삭제만 있습니다.
- [ ] 시작할 때 기록한 `git status --short`와 지금 결과를 비교해, 새로 바뀐 파일이 대상 컨텍스트 파일과 `docs/context-file-audit.md`뿐입니다. 홈 디렉터리의 전역 설정은 수정하지 않았습니다.
- [ ] 삭제한 A 줄이 가리키던 명령과 구조가 `package.json`, 설정 파일, 코드에서 여전히 확인됩니다.
- [ ] `docs/context-file-audit.md`에 점검 날짜, 줄별 표(파일, 줄 번호, 분류, 근거, 결정), 삭제한 줄의 원문 전문과 원래 줄 번호가 모두 있습니다.
- [ ] `git rev-parse HEAD`가 시작할 때와 같습니다. 커밋, stash, push를 하지 않았습니다.
- [ ] 성능이나 비용이 좋아졌다고 보고하지 않았습니다.
