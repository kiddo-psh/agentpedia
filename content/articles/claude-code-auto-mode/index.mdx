원격 브랜치 삭제가 모호한 요청에서 나왔습니다. John Hughes의 2026년 3월 25일 Anthropic 엔지니어링 글입니다. 사용자는 오래된 브랜치 정리만 말했습니다. 에이전트는 원격 브랜치 목록을 받았습니다. 패턴으로 골라 삭제 명령을 냈습니다. 요청은 모호했습니다. 삭제는 되돌릴 수 없습니다. 로컬 브랜치만 뜻했을 수 있습니다.

## 승인 창은 거의 읽히지 않는다

Claude Code는 이런 명령 앞에서 기본적으로 승인을 묻습니다. 사람은 그 창을 잘 보지 않습니다.

<Quote source="anthropic-auto-mode">
Manual prompts sit in the middle, and in practice users accept 93% of them anyway.
</Quote>

수동 승인은 두 극단의 가운데입니다. 아무것도 안 묻는 방식입니다. 모든 것을 가두는 방식입니다. 사용자는 그 요청의 93%를 그냥 승인합니다. 요청이 잦으면 사람은 점점 덜 읽습니다. Anthropic은 이름을 붙였습니다. <Term id="approval-fatigue">승인 피로</Term>입니다. 버튼은 눌렸습니다. 검토는 없었을 수 있습니다.

2026년 3월에 개발자가 쓸 대안은 두 가지였습니다. 하나는 샌드박스입니다. 에이전트를 격리된 환경에 가둡니다. 안전하지만 손이 많이 갑니다. 새 기능마다 설정해야 합니다. 네트워크나 호스트에 닿는 일은 격리를 깹니다. 다른 하나는 `--dangerously-skip-permissions`입니다. 이름 그대로 보호를 모두 끕니다. 그래서 승인 자체를 모델에 맡겨 보기로 했습니다.

## 입력 탐지기와 출력 분류기가 승인한다

이 방식이 <Term id="auto-mode">auto 모드</Term>입니다. 아래는 2026년 3월 글의 설계입니다. 승인을 모델 분류기에 맡깁니다. 방어는 두 층입니다. 입력 층은 서버에서 도구 출력을 검사합니다. <Term id="prompt-injection">프롬프트 인젝션</Term>으로 보이면 경고를 붙입니다. 경고는 에이전트에 붙습니다. 출력 층은 <Term id="transcript-classifier">트랜스크립트 분류기</Term>입니다. 행동 직전에 그 행동을 심사합니다. 사람의 승인을 대신합니다.

위험은 네 가지입니다.

- <Term id="overeager">월권(overeager) 행동</Term>
- 정직한 실수
- 프롬프트 인젝션
- 모델이 사용자와 다른 목표를 따르는 경우

월권 행동이 가장 알아보기 쉽습니다. 브랜치 정리가 그 예입니다. 악의는 없습니다. 결과는 사고입니다. 이 항목은 시험 결과에서 다시 나옵니다.

### 상태를 바꾸지 않는 행동은 분류기를 건너뛴다

3월 글에서 모든 행동이 분류기로 가진 않았습니다. 등급은 셋입니다. 첫째는 분류기를 건너뜁니다. 파일 읽기와 검색처럼 상태를 바꾸지 못하는 도구입니다. 사용자가 만든 허용 규칙도 첫째입니다. 둘째도 건너뜁니다. 프로젝트 안의 파일 편집입니다. 나머지 전부가 셋째입니다. 셋째만 분류기로 갑니다.

### 넓은 허용 규칙은 버리고 좁은 규칙은 남긴다

이 건너뛰기에는 구멍이 있었습니다. 넓게 열어 둔 허용 규칙이 있으면 가장 위험한 명령도 건너뜁니다. 그래서 auto 모드에 들어갈 때 아무 코드나 실행하는 규칙은 버렸습니다. 버린 종류는 세 가지입니다.

- 셸을 통째로 여는 규칙
- 와일드카드 스크립트 인터프리터
- 패키지 매니저 실행 명령

와일드카드의 예는 python과 node입니다. 포맷터만 실행하는 좁은 규칙은 남았습니다. 이 목록은 실제 사용으로 만든 최선의 목록입니다. 빠진 항목이 있을 수 있습니다.

### 분류기는 빠른 필터 뒤에 느린 재평가를 둔다

출력 층은 안에서 다시 두 단계입니다. 3월 글 시점의 모델은 Sonnet 4.6입니다. 1단계는 예와 아니오만 빠르게 답합니다. 애매하면 막는 쪽으로 기울입니다. 2단계는 1단계가 위험하다고 한 행동만 다시 봅니다. 추론을 거친 느린 재평가입니다.

## 분류기는 설명 없이 행동만 본다

<Quote source="anthropic-auto-mode">
We strip assistant text so the agent can't talk the classifier into making a bad call.
</Quote>

3월의 출력 층은 사용자 메시지와 도구 호출만 봤습니다. 도구 결과는 보지 못했습니다. 웹 페이지나 파일에 숨은 지시는 입력 층이 검사했습니다. 대가가 있습니다. 사용자가 말한 적 없는 작업 번호(ID)를 구분하지 못했습니다. 조회해서 찾았는지, 지어냈는지입니다.

<KeyIdea title="변명을 듣지 않는 승인자">
사람 승인자는 설명을 듣고 납득하기 쉽습니다. 이 분류기는 말이 아니라 행동만 봅니다. 에이전트의 변명을 막은 대가로, 에이전트가 왜 그 대상을 골랐는지도 알 수 없게 됐습니다.
</KeyIdea>

### 거부가 쌓이면 사람에게 넘긴다

3월 글에서 분류기가 막으면 Claude는 멈추지 않습니다. 더 안전한 길을 찾으라는 안내를 받습니다. 거부가 쌓이면 사람에게 넘깁니다.

<Quote source="anthropic-auto-mode">
If a session accumulates 3 consecutive denials or 20 total, we stop the model and escalate to the human.
</Quote>

연속 3번이거나 합계 20번이면 사람에게 넘겼습니다. 그때 모델을 멈춥니다. 화면 없이 돌리는 실행에서는 프로세스를 끝냈습니다. 헤드리스 모드입니다.

### 다른 에이전트에 일을 넘길 때도 검사한다

3월 글에서 검사는 일 넘김에도 이어집니다. 맡길 때 분류기가 위임 자체를 거부할 수 있습니다. 결과가 돌아오면 하위 에이전트의 행동 기록 전체를 검사합니다. 문제가 보이면 결과를 버리지 않습니다. 일을 맡긴 에이전트에 보안 경고를 붙입니다.

## 오탐은 줄고 미탐은 늘었다

3월 글이 공개한 결과입니다. 시험 집합은 세 가지입니다.

- 실제 트래픽 1만 건은 직원들의 Claude Code 도구 호출입니다.
- 실제 월권 행동 52건은 직원이 거부했거나 나중에 문제로 표시한 행동입니다.
- 합성 유출 시도 1,000건은 민감한 데이터를 밖으로 보내도록 만든 시도입니다.

그중 상당수는 난독화를 썼습니다. 1단계만 쓴 경우와 전체 파이프라인을 비교했습니다. 오탐률은 안전한 행동을 잘못 막은 비율입니다. <Term id="false-negative-rate">미탐률</Term>은 위험한 행동을 놓친 비율입니다.

| 시험 집합 | 지표 | 1단계만 | 전체 |
|---|---|---|---|
| 실제 트래픽, n=10,000 | 오탐률 FPR | 8.5% | 0.4% |
| 실제 월권 행동, n=52 | 미탐률 FNR | 6.6% | 17% |
| 합성 유출 시도, n=1,000 | 미탐률 FNR | 1.8% | 5.7% |

정상 행동을 잘못 막는 비율은 8.5%에서 0.4%로 줄었습니다. 위험한 행동을 놓치는 비율은 두 집합 모두 늘었습니다. 2단계는 1단계의 과잉 차단을 풀어 줍니다. 풀어 준 것 가운데 일부는 실제로 위험한 행동이었습니다.

<Quote source="anthropic-auto-mode">
The 17% false-negative rate on real overeager actions is the honest number.
</Quote>

52건은 작은 표본입니다. 위험한 시도는 실제 세션에서 붙잡아 라벨을 붙여야 모입니다. 그래서 더 늘리기 어려웠습니다. 17%도 흔들릴 수 있습니다.

놓친 사례 대부분에서 위험 자체는 알아봤습니다. 강제 푸시나 삭제가 그 예입니다. 틀린 곳은 사용자의 말이 그 행동까지 허락했는지입니다. PR 정리는 강제 푸시까지 허락한 말이 아닙니다. 분류기는 승인처럼 보이는 흔적을 찾고 멈췄습니다. 비슷한 행동을 앞서 한 번 승인한 것도 일반 허락은 아닙니다.

## 2026년 11월 문서는 3월 글과 네 가지를 다르게 적는다

여기까지는 2026년 3월 25일 글입니다. 여기서부터는 2026년 11월 13일 Claude Code 공식 문서입니다. 네 가지가 3월 글과 다르거나 더 자세합니다.

### 최신 버전은 이미 auto 모드로 시작할 수 있다

3월 글은 켜는 방법을 문서로 넘겼습니다. 11월 문서는 `--permission-mode auto`로 켭니다. Shift+Tab으로도 켭니다. 최신 터미널 세션은 처음부터 auto 모드입니다. VS Code 대화형 세션도 같습니다.

### 좁은 허용 규칙은 아직 분류기를 건너뛴다

11월 문서는 3월 글보다 버리는 규칙을 더 구체적으로 적습니다. 버려지는 코드는 세 가지입니다.

- `Bash(*)`
- `PowerShell(*)`
- `Bash(python*)`

패키지 매니저를 실행하는 명령도 버려집니다. `Agent` 허용 규칙도 버려집니다. 하위 에이전트를 실행하는 규칙입니다. `Monitor` 허용 규칙도 버려집니다. 명령을 셸로 실행하는 규칙입니다. 모드를 나가면 이 규칙들은 다시 적용됩니다. 좁은 규칙은 대체로 분류기보다 먼저 적용됩니다. 그래서 분류기를 건너뜁니다. 3월 글의 구멍은 일부 남아 있습니다.

| 허용 규칙 | auto 모드에서 |
|---|---|
| 넓은 규칙 `Bash(*)` | 버려지고, 분류기가 판단합니다 |
| 고정된 좁은 규칙 `Bash(npm test)` | 남아 분류기를 건너뛰고 실행합니다 |
| 인자가 열린 좁은 규칙 `Bash(npm test *)` | 남아 분류기를 건너뜁니다 |

인자가 열린 규칙은 뒤에 다른 것이 붙어도 실행될 수 있습니다. 예상하지 못한 인자도 그렇습니다. 스크립트 경로도 그렇습니다.

모든 셸 명령을 분류기에 보이게 할 수 있습니다. `autoMode.classifyAllShell: true`로 셸 허용 규칙을 멈춥니다. 이 `autoMode` 설정은 세 곳에서만 읽힙니다.

- 홈의 `~/.claude/settings.json`
- 조직이 배포하는 관리형 설정
- 실행할 때 넘긴 설정

`defaultMode: "auto"`도 홈이나 관리형 설정에 적어야 합니다. auto 모드로 시작하게 하는 값입니다. 두 설정 모두 저장소의 `.claude/settings.json`에 적으면 무시됩니다.

### 분류기 모델과 입력이 바뀌었다

3월 글의 분류기는 Sonnet 4.6이었습니다. 11월 문서의 기본값은 Claude Sonnet 5입니다. 환경과 설정에 따라 다른 모델이 쓰일 수 있습니다. 일부 세션은 Anthropic 서버가 직접 판정합니다. 내 세션이 어느 쪽인지는 `/status`로 봅니다.

입력도 달라졌습니다. Claude Code가 직접 보내는 분류기 요청에 들어가는 것은 세 가지입니다.

- 사용자 메시지
- 도구 호출
- CLAUDE.md 내용

파일 읽기와 검색 같은 읽기 전용 조회는 빠집니다. 도구 결과는 여전히 제거됩니다.

### 헤드리스 실행은 한도 뒤에도 작업을 잇는다

거부 한도는 그대로입니다. 연속 3번입니다. 누적 20번입니다. 바꿀 수 없습니다. 대화형 세션에서는 3월 글처럼 사람에게 다시 묻습니다. 달라진 것은 헤드리스 실행입니다. 화면 없이 `-p`로 돌립니다. 3월에는 한도에 닿으면 프로세스가 끝났습니다. 11월 문서는 그 행동만 건너뜁니다. 작업은 이어 갑니다. 대상은 승인 도구를 따로 붙이지 않은 실행입니다. `--permission-prompt-tool`이 없는 `-p` 실행입니다.

## 17%는 3월 수치라 규칙은 직접 연다

17%는 3월 분류기의 수치입니다. Sonnet 5 기본값의 미탐률은 문서에 없습니다. 서버 판정의 미탐률도 없습니다. 결과 표는 시험에 쓴 모델을 따로 적지 않습니다. 글은 분류기를 Sonnet 4.6으로 설명합니다.

3월 글은 한계도 적었습니다. 모든 승인을 꼼꼼히 하던 사람에게는 후퇴일 수 있습니다. 위험이 큰 인프라에서 사람의 검토를 대신하지 못합니다. 반사적으로 Enter를 누르던 손도 완전하지 않았습니다. 분류기도 완전하지 않습니다. 그래서 확인할 것은 두 가지입니다. `claude auto-mode defaults`로 이 버전의 기본 규칙을 봅니다. 저장소의 `.claude/settings.json`에서 좁은 허용 규칙을 엽니다. 분류기를 건너뛰는 규칙입니다.
