Code Mode는 기본으로 꺼져 있습니다. Anthropic의 ClaudeDevs가 2026년 11월 17일(UTC) X에 알렸습니다. 실험 기능 <Term id="cc-code-mode">Code Mode</Term>입니다. 켜려면 `CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1`이 필요합니다.

<Quote source="claude-devs-code-mode">
Check out Code Mode, a new, experimental way for Claude Code to work with tools. Claude writes scripts that chain your tools together in sophisticated ways, and it can answer you while long commands are still running.
</Quote>


## 한 호출이 곧 안전은 아니다

평소 Claude Code는 도구를 한 번 부르고 결과를 읽습니다. 그다음 호출을 고릅니다. 도구는 다음입니다.

- Bash
- Read
- Edit

사람이 중간 결과에 끼어들기 쉽습니다. 그래서 한 호출씩 보면 안전하다는 감각이 생깁니다.

Code Mode는 그 감각을 흔듭니다. Claude는 같은 작업을 JavaScript 한 덩어리로 씁니다. Claude Code가 그 코드를 세션에서 실행합니다. 코드는 명령을 병렬로 돌릴 수 있습니다. 한 결과로 다음 호출을 고를 수 있습니다. 모델이 읽을 부분만 돌려줄 수 있습니다.

<KeyIdea title="중간 판단이 스크립트로 들어갑니다">
자유 턴에서는 모델이 결과를 본 뒤 다음을 고릅니다. Code Mode에서는 걸러 내기와 분기가 실행 중에 일어납니다. 대화에는 호출과 결과의 일부만 보입니다. 스크립트 전문은 트랜스크립트 뷰어에 있습니다. 단축키는 `Ctrl+O`입니다.
</KeyIdea>

문서의 예는 재시도 한도를 올리는 일입니다. 한 스크립트가 다음을 합니다.

- 파일을 찾습니다.
- 고칩니다.
- 테스트를 돌립니다.

```javascript
const files = await $`rg -l "function retryPolicy" src`.text();
const target = files.trim().split("\n")[0];
await edit(target, "maxAttempts: 3", "maxAttempts: 5");
({ edited: target, tests: $`npm test -- retryPolicy`.nothrow() });
```


대화 화면에는 편집 diff가 보입니다. 위 코드는 기본적으로 접혀 있습니다.

## 여러 호출이 이어질 때 스크립트를 쓴다

문서는 다음 작업에 Code Mode를 권합니다.

- 여러 파일에 같은 변경이 반복됩니다.
- 검색 결과를 걸러 읽을 양을 줄입니다.
- 서로 독립인 명령을 동시에 돌립니다.

자유 턴이 맞는 작업도 있습니다.

- 한두 번 읽고 방향을 정하는 탐색입니다.
- 사람과의 짧은 계획 대화입니다.
- 호출마다 판단을 눈으로 보는 작업입니다.

스크립트로 묶으면 중간 출력이 컨텍스트에 덜 올라갑니다. 사람은 그 출력을 대화에서 보기 어려울 수 있습니다. 왕복도 줄어듭니다.

API에는 비슷한 기능이 있습니다. <Term id="programmatic-tool-calling">프로그램형 도구 호출</Term>입니다. 모델이 코드 실행 안에서 도구를 함수처럼 잇습니다. 중간 결과는 코드가 처리합니다. 최종 출력만 모델 컨텍스트로 올라갑니다. 부를 도구는 개발자가 `allowed_callers`로 정합니다. Claude Code에서는 권한 규칙이 동작을 가릅니다. <Term id="agent-hook">훅</Term>도 동작을 가릅니다.

## 분류기는 스크립트만 보고 실행 값은 못 본다

<Term id="auto-mode">auto 모드</Term>와 함께 쓰면 심사 단위가 바뀝니다. <Term id="transcript-classifier">분류기</Term>는 코드 덩어리를 심사합니다. 도구를 하나씩 심사하지 않습니다.

<Quote source="cc-docs-code-mode">
Auto mode: the classifier reviews each piece of code before it runs, not each tool call. It doesn't see values computed at run time, such as a path taken from search output, so keep rules or hooks for calls you must control.
</Quote>


검색으로 고른 경로는 분류기 눈에 들어오지 않습니다. 실행 중에 정해지기 때문입니다. 반드시 막을 호출은 규칙으로 남깁니다. 훅으로 남기기도 합니다.

deny 규칙과 ask 규칙은 스크립트 안의 각 호출에 적용됩니다. PreToolUse 훅도 도구 이름 그대로 적용됩니다. Bash 훅은 명령 조각까지 봐야 합니다. `app`에서 `git push`를 하면 훅 입력은 `cd 'app' && git push`일 수 있습니다. 스크립트 텍스트는 matcher `REPL`로 봅니다. JavaScript는 `tool_input.code`에 있습니다.

| 계층 | 보는 것 | 놓치기 쉬운 것 |
|---|---|---|
| auto 분류기 | 실행 전 스크립트 | 나중에 정해진 값 |
| deny·ask·Bash | 호출의 명령 | 다른 표기 |
| PreToolUse | 호출 입력 | 검사 밖 필드 |
| REPL 훅 | 스크립트 전체 | 실행 중에만 있는 값 |

Code Mode는 auto 모드의 빈칸을 메우지 않습니다. 분류기가 보는 단위를 스크립트로 바꿉니다. 개별 호출을 더 잘 보여 주는 기능이 아닙니다.

## 켜기 전에 요건과 한계를 본다

Code Mode 세션은 기능이 켜진 터미널에서만 이어집니다. 코드가 백그라운드로 가지 않으면 끝날 때까지 기다립니다. 권한 프롬프트 시간을 넣어 10분에서 멈춥니다.

쓸 수 없는 기능은 다음입니다.

- Remote Control
- Chrome
- 컴퓨터 사용
- 데스크톱으로 옮기기
- 백그라운드 세션으로 바꾸기

동작하지 않는 곳도 있습니다.

- `-p`
- Agent SDK
- VS Code 패널
- 클라우드 세션

버전은 Claude Code v2.1.323 이상입니다. 네이티브 설치가 필요합니다. Anthropic API에 직접 붙는 계정이 필요합니다. 구독 계정이나 Console 계정입니다.

다음이 겹치면 시작되지 않을 수 있습니다.

- 게이트웨이
- Bedrock
- 일부 클라우드 호스팅
- HIPAA
- 제로 데이터 보존
- API 키 헬퍼
- OpenTelemetry 내보내기
- `DISABLE_TELEMETRY`

프로젝트 settings는 이 환경 변수를 무시합니다. 사용자 설정에서 켭니다. 셸에서 켤 수도 있습니다. 조직은 관리형 설정에 `0`을 넣어 막을 수 있습니다.

관련 호출이 많은 세션에만 켜는 편이 문서의 취지입니다.

## 한계

Code Mode에서는 PreToolUse 타임아웃이 다를 수 있습니다. 실패 처리도 다를 수 있습니다. 스크립트 자체의 위험 패턴은 `REPL` 훅으로 검사합니다. 공식 문서는 코드를 어느 가상 머신이나 샌드박스에서 돌리는지 밝히지 않습니다. 한 호출씩 보는 습관이 안전을 보장하지는 않습니다.
