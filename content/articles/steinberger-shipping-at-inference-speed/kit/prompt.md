# 목표: 에이전트가 스스로 검증할 수 있는 CLI 진입점 만들기

피터 스타인버거의 "무엇을 만들든 CLI부터" 원칙을 이 레포에 적용한다.
CLI가 있으면 에이전트가 직접 실행하고 출력을 확인할 수 있어 검증 루프가 닫힌다.

## 0. 맞는지 먼저 판단하기

레포를 읽고 아래를 확인한다. 하나라도 해당하지 않으면 **변경하지 말고 멈춘 뒤** 이유를 사용자에게 알린다.

- 지금은 UI나 수동 조작으로만 동작을 확인할 수 있는 핵심 기능이 있다.
- 그 기능의 로직이 화면 코드와 분리된 함수(또는 모듈)로 호출할 수 있다.
- 그 기능을 실행하는 CLI나 스크립트가 아직 없다. (이미 있다면 새로 만들 필요가 없으므로 멈추고, 있는 명령의 위치를 알린다.)

## 1. 계획을 보여주고 승인받기

변경 전에 다음을 담은 계획을 보여주고 **사용자의 승인을 받은 뒤에만** 진행한다.

- 고른 핵심 기능과 고른 이유
- 호출할 기존 함수의 위치
- 추가할 CLI 명령의 이름, 입력(인자나 파일), 출력 형태
- 추가하거나 수정할 파일 목록 (CLI 파일, 매니페스트의 scripts 항목·의존성, README 또는 AGENTS.md/CLAUDE.md)
- 이 함수의 부수 효과(DB·파일 쓰기, 네트워크 호출, 메시지 발송)와 3단계에서 실행할 때 쓸 입력. 부수 효과가 있으면 테스트 데이터·로컬 환경·dry-run으로만 실행하는 방법

## 2. CLI 만들기

- 기존 함수를 그대로 호출하는 가장 작은 CLI 명령을 만든다. 로직을 복사하거나 다시 구현하지 않는다.
- 출력은 사람과 에이전트가 모두 읽기 쉬운 텍스트로 낸다. JSON 옵션은 새 의존성 없이 표준 라이브러리로 될 때만 두고, 계획에 밝힌다.
- 레포가 이미 쓰는 언어와 도구를 따른다. 새 의존성은 꼭 필요할 때만, 잘 관리되고 널리 쓰이는 것으로, 계획에 밝힌 뒤 추가한다.
- UI나 기존 화면 코드는 수정하지 않는다.

## 3. 실행해서 확인하기

- 운영 데이터나 외부 서비스에 쓰는 실행은 하지 않는다. 안전한 입력이 없으면 실행하지 말고 멈춘 뒤 알린다.
- 만든 CLI를 **직접 실행해** 출력이 기대와 맞는지 확인한다. 실행 명령을 추측해서 문서에 적지 않는다.
- 레포에 테스트·타입 체크·린트 명령이 있으면 실행해 기존 동작이 깨지지 않았는지 확인한다.
- CLI 실행이나 기존 검사가 실패하면 계획에 없는 파일을 고치지 말고, 실패한 명령과 출력을 사용자에게 보여준 뒤 다음 단계를 묻는다.

## 4. 문서에 남기기

README 또는 AGENTS.md/CLAUDE.md에 다음을 적는다.

- CLI 실행 명령 (3단계에서 실제로 실행한 그대로)
- 실제 출력 예시
- 에이전트가 이 기능을 바꾼 뒤 이 명령으로 결과를 확인하라는 한 줄 안내
