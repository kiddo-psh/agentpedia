2026년 10월 28일 GitHub Changelog는 GitHub-verified <Term id="mcp">MCP</Term> 서버, 곧 <Term id="copilot-connector">Copilot 커넥터</Term>를 공개 프리뷰로 내놓았다고 알렸습니다. 발표의 핵심은 설치 편의만이 아닙니다. 개발자마다 서버 URL과 자격 증명을 직접 관리하던 일을, 한 번 연결하고 조직이 허용 목록으로 통제하는 연결 계층으로 옮기겠다는 쪽입니다.

## MCP는 그동안 각자 로컬에 붙이는 확장이었다

많은 팀은 `.mcp.json`이나 IDE 설정에 MCP 서버 명령·URL을 적어 둡니다. 서버를 찾고, 로컬에 두고, 자격 증명을 넣고, Copilot 앱과 CLI와 VS Code마다 같은 설정을 반복합니다. 유연하지만 출처와 권한이 사람마다 달라집니다.

GitHub는 그 반복을 줄이겠다고 말합니다.

<Quote source="gh-changelog-connectors">
Pick a service, sign in, and you're done. There's no server to find, nothing to install locally, and no credentials to manage.
</Quote>

서비스를 고르고 로그인하면 끝이며, 로컬에 서버를 두거나 자격 증명을 직접 관리하지 않는다는 뜻입니다. 공식 문서(2026년 11월 21일 열람)도 GitHub가 MCP 서버 설정과 인증을 대신한다고 적습니다.

## 한 번 연결하면 여러 Copilot 화면에서 같이 쓴다

Changelog는 한 곳에서 연결한 서비스가 GitHub Copilot 앱, Copilot CLI, VS Code, Copilot in the cloud, GitHub Mobile에서 추가 설정 없이 동작한다고 적었습니다. Copilot은 요청과 관련될 때 연결된 서비스의 도구를 쓰고, 앱에서는 일정에 맞춰 연결된 서비스로 자동화를 둘 수도 있습니다.

출시 당시 연결 가능한 서비스는 26개였습니다. Slack, Figma, Notion, Sentry, Linear, Atlassian Rovo, Cloudflare, Vercel, Work IQ 등이 포함됐습니다. 2026년 11월 18일 Changelog는 Supabase, Box, Calendly 등 8개를 더해 이미 25개 넘게 연결할 수 있다고 알렸습니다. 목록은 계속 늘어납니다.

<KeyIdea title="MCP를 연결 계층으로 옮긴다">
GitHub-verified MCP 서버는 개발자 로컬 확장만이 아니라, 한 번 인증하고 여러 Copilot 화면에서 쓰며 조직이 허용 목록으로 통제하는 연결 계층에 가깝습니다. 유연한 로컬 설정이 사라진다는 뜻이 아니라, 기본 경로가 바뀐다는 뜻입니다.
</KeyIdea>

## 조직은 허용 목록에 커넥터를 넣어야 한다

Business·Enterprise에서 쓰려면 관리자가 `Editor preview features` 정책을 켜야 합니다. 엔터프라이즈가 managed settings의 <Term id="mcp-allowlist">MCP 허용 목록</Term>을 쓰면, 관리자가 GitHub-verified MCP 서버를 그 목록에 넣어야 합니다. 일부 서비스(예: Slack MCP)는 해당 서비스 쪽 관리자 허용도 필요합니다.

2026년 11월 21일 공식 문서 기준으로, 허용 목록을 정의하면 목록에 맞는 커넥터만 쓸 수 있습니다. 모든 커넥터를 허용하려면 `https://api.github.com/copilot-connectors/api/v1/connectors/*/mcp` 같은 와일드카드를 넣고, 일부만 허용하려면 서비스별 URL을 적습니다. `deniedMcpServers`에 걸리면 허용 목록에 있어도 막힙니다. MCP 서버 정책이 꺼져 있거나, 레지스트리 전용 제한이 `Registry only`이면 커넥터도 막힐 수 있습니다.

## 로컬 MCP를 전부 없애라는 말은 아니다

공식 문서도 키 기반 인증이 필요한 로컬·원격 커스텀 MCP를 함께 쓸 수 있다고 적습니다. 커넥터는 GitHub Actions에서 이슈를 Copilot에 할당할 때처럼 Actions 기반 세션에서는 아직 지원되지 않습니다. 사설 서버, 내부 API, 레지스트리에 없는 도구는 로컬·사설 MCP로 남을 수 있습니다.

더 중요한 경계가 있습니다. 2026년 11월 21일 공식 문서 기준으로 커넥터는 Copilot 앱·CLI·VS Code·클라우드·Mobile 같은 **지원되는 Copilot 화면**에서 씁니다. Cursor나 Claude Code의 `.cursor/mcp.json`·Claude MCP 설정을 Copilot에서 서비스를 연결했다고 지워도, 그 클라이언트에는 대체가 생기지 않습니다. 같은 서비스라도 클라이언트별로 설정이 갈립니다.

먼저 할 일은 지금 붙어 있는 서버를 모아, Copilot 쪽에서 검증된 커넥터를 쓸지·사설로 둘지·허용 목록에 넣을지를 나누는 일입니다. 출처가 불분명한 서버를 찾는 일반 신뢰 경계 점검은 다른 글의 범위입니다. 이 글의 초점은 연결 계층으로 옮길 후보를 가리는 데 있습니다.

커넥터 목록과 정책 이름은 공개 프리뷰라 바뀔 수 있습니다. 허용 목록 문법과 정책 키는 작성 시점의 공식 문서를 다시 확인하는 편이 안전합니다.
