# 목표: 차분 시험 비교표의 회귀 수를 비워 두기

Addy Osmani는 검사가 자기를 심판하는 규칙을 고칠 수 있으면 그 검사가 깨진다고 썼다. 이 키트는 시험 없이 맡긴 리팩터와 차분 시험을 둔 경우를 비교할 표를 만들고, 회귀 수는 비운다. 순수 함수가 있을 때만 그 함수를 바꾸지 않는 시험 파일 하나를 추가하고 실행한다. `REVIEW.md`는 만들지 않는다.

## 절대 지킬 것

- 승인받기 전에는 파일을 만들거나 고치지 않는다.
- 검증 명령을 CLAUDE.md·AGENTS.md에 덧붙이지 않는다. 그건 Boris Cherny 키트 범위다.
- `REVIEW.md`와 `docs/verifier-honesty.md`를 만들거나 고치지 않는다. 그건 자기 검증 키트 범위다.
- 회귀 개수, 성공률, 10점 같은 숫자를 추정해 적지 않는다.
- 함수 본문과 애플리케이션 로직을 수정하지 않는다. 커밋, 푸시, 설치, 포맷(`--fix`)을 하지 않는다.
- 순수 함수가 없거나 테스트 명령이 파일을 바꾸면 시험 파일을 만들지 않고 멈춘다.

## 0. 맞는지 먼저 판단하기

테스트 명령 이름과, 입출력이 순수해 보이는 함수 하나를 찾는다. 둘 중 하나가 없으면 이유를 설명한 뒤 여기서 멈춘다.

## 1. 빈 표 계획을 보여주고 승인받기

`docs/differential-gate-trial.md`에 넣을 두 칸을 먼저 보여 준다. 칸은 "시험 없음"과 "차분 시험"이고, 회귀 수는 빈칸이다. 시험 파일을 만들 경로와, 옛 동작을 정답으로 두고 같은 입력을 두 번 비교한다는 문장만 적는다. 승인 전에는 파일을 만들지 않는다. 같은 이름이 있으면 덮어쓰지 말고 다른 이름을 제안한 뒤 고를 때까지 멈춘다.

## 2. 승인 뒤에만 시험 파일을 추가하고 실행하기

승인한 경우에만, 그 함수를 수정하지 않는 시험 파일 하나를 추가한다. 파일을 바꾸지 않는 테스트 명령으로 실제로 실행한다. 빌드, 설치, 스냅샷 갱신이 필요하면 실행하지 않고 이름만 적는다. 실패하면 함수를 고치지 않고 실패 그대로 적는다.

## 3. 보고서에 결과만 옮기기

`docs/differential-gate-trial.md`에 명령, 통과 여부, 빈 회귀 칸을 적는다. 만든 파일과 시험 출력을 다시 읽어 숫자가 실행에서 온 것만 남았는지 확인한다.
